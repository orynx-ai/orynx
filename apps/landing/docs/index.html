From install to pull request.

Everything you need to run Orynx: install it, connect your tools, and hand your coding agent a ticket while you watch and approve.

What Orynx is

Orynx is an app on your own machine. It brings the Jira tickets, GitHub pull requests and Slack and Discord messages that need you into one inbox, and runs your coding agent, Claude or Codex, on a ticket in its own git worktree while you watch, approve and ship.

  • A small server runs on your machine at 127.0.0.1:4317. It talks to Jira, GitHub, Slack, Discord, Claude and Codex with your own logins.
  • The app is a web page served by that server. Open it in a browser, install it as an app, or reach it from your phone at https://orynx.local.
  • There is no Orynx cloud. Tokens live in your OS keychain, and tickets, pull requests and messages are cached in a file on your disk.

The rest of this guide follows the path of a first day: install, connect, then take a ticket to a pull request.

Install

Orynx runs on macOS and Linux. You need:

  • Node 24, or nvm to install it
  • Claude Code or Codex 0.166 or later, signed in on this machine (or both)
  • A Jira Cloud API token, and the gh CLI or a GitHub token
  • Optional: a Slack app your workspace admin approves, or a Discord bot you make

Clone the repository and run its install script:

The script:

  1. Uses Node 24, through nvm if you have it, and builds Orynx.
  2. Makes a certificate for orynx.local in ~/.devhub/tls, and asks for your machine's password once so this machine trusts it.
  3. Starts Orynx whenever you log in: a LaunchAgent on macOS, a systemd user service on Linux.

Keep the clone. install.sh builds the folder it sits in, so there is no curl | sh. Updates come from the same folder.

Set up Orynx

Open http://127.0.0.1:4317 on this machine. Until setup is done, every page shows Set up Orynx.

  1. Picture, optional: press Add picture and crop it.
  2. Name, filled in from your git user.name. Change it if you like.
  3. Bio, optional, up to 160 characters.
  4. Password and Confirm password, at least 8 characters. Your phone and other devices on your wifi ask for it at orynx.local.
  5. Press Finish setup. Home opens.

This machine never asks for the password: http://127.0.0.1:4317 and https://orynx.local both open straight away. Until you finish setup here, other devices see only "Finish setting up Orynx", so nobody else on the wifi can choose the password.

To change your name, bio, picture or password later, open the profile menu at the bottom of the sidebar and pick your name. Changing the password signs your other devices out.

Connect your tools

Open Settings › Connections. Each tool shows Connected, Needs reconnecting or Not connected; select its status to manage it. Orynx uses your own logins, so it never sees more than you can.

Claude and Codex

There is nothing to connect. Orynx uses the login your coding agent already has on this machine. Check it in Settings › Coding agent: each agent's card says Active and who you are signed in as. You need one of them; Orynx works with both.

  • Claude uses Claude Code's login: a claude.ai account, an API key, Amazon Bedrock or Google Vertex AI. If it says Not signed in, run claude in a terminal, sign in, then press Check again.
  • Codex uses the codex already on this machine, version 0.166 or later, and its ChatGPT sign-in or API key. Orynx ships no Codex and never keeps an OpenAI key. If it says Not installed, run npm install -g @openai/codex; if it says Not signed in, run codex login. Then press Check again.

Jira

Orynx works with Jira Cloud (your-team.atlassian.net).

  1. Create an API token at id.atlassian.com › Security › API tokens.
  2. In Settings › Connections, open Jira and fill in Jira site, Email and API token.
  3. Press Connect. Orynx reads the issues assigned to you, your sprint and their comments.

Test connection checks it any time. When a token expires, Jira shows Needs reconnecting: paste a new token and press Reconnect.

GitHub

Open GitHub and pick how to connect:

  • Use my gh login: Orynx asks the gh command-line tool for your token each time and keeps no copy. Picked for you when gh is installed.
  • Use a personal access token: a classic token with the repo scope, or a fine-grained token. If your company uses single sign-on, authorize the token for it. Orynx keeps it in your keychain.

Orynx reads pull requests, checks and review comments, and pushes session branches and opens pull requests only on your click or a permission you turned on. It works with github.com.

Slack

Reading your Slack mentions needs a Slack app your workspace admin approves. Open Slack:

  1. Ask your Slack admin to approve the Orynx app. Press Copy request for your admin and send it to them. It names the scopes Orynx needs, only for your account.
  2. Paste your Slack token: the User OAuth Token from your Slack app, starting xoxp-. Press Connect. Orynx checks the token and its scopes before it saves anything.

Orynx reads your mentions, your DMs and the threads you add. It writes only a pull request's link in a thread, on your click.

Discord

Orynx reads Discord through a bot you make, because Discord forbids automating a person's account. Open Discord:

  1. Make a Discord bot for Orynx. In Discord's Developer Portal: New Application, then Bot. Turn on Message Content Intent, and add the bot to your servers with View Channels, Read Message History, Send Messages and Send Messages in Threads.
  2. Paste your bot's token from the bot's page in the Developer Portal, and press Connect. If a team owns the bot, Orynx also asks for Your Discord user ID: in Discord, turn on Developer Mode, then right-click your name › Copy User ID.

Orynx reads mentions of you in your bot's servers and the threads you add. It writes only a pull request's link in a thread, as your bot, on your click.

Both tokens live in your keychain. Until a tool is connected, its messages are left out of your inbox.

Add your repositories

Claude works only in folders you add. Open Settings › Repositories and press Add local folder.

  1. Folder: the full path of a git repository, like ~/code/web-app, or press Choose folder.
  2. Jira project, optional: tickets from this project open in this folder.
  3. Press Add folder.

Each folder's More actions menu has Edit, Duplicate (to map the same folder to a second Jira project) and Delete. Deleting only removes it from Orynx; the folder stays on disk.

How Orynx picks the folder for a task

  • A ticket's key picks the folder mapped to its project: PROJ-1423 opens in the folder for PROJ. If several match, Orynx asks.
  • A pull request picks the folder whose git remote is that repository.
  • Otherwise Orynx uses the folder you used last, or your only one. Change it any time from the composer's Repository menu.

Choose what the agent may do

Open Settings › Coding agent. Under What the agent can do without asking, start from a level, then change any row. Anything set to Ask waits for your click in the session. Changes save automatically. The same rows decide for Claude and for Codex.

A fresh Orynx shows Custom: the agent edits files freely, asks before any command, and never pushes or opens a pull request by itself. You still can, with one click.

  • Rules for sets the rules for all repositories or gives one repository its own.
  • Allowed commands run without asking, inside the sandbox with no network, when Run commands is set to Allowed only. Add one here, or press Always allow when the agent asks.

Home and the inbox

Home answers two questions: what should your agent build next, and who is waiting on you. The composer is at the top and Needs your attention is below it.

Needs your attention

One list of the tickets, pull requests and messages that need you, in tabs All, Jira and Pull requests, plus Slack and Discord once each is connected. Every row says why it is there and for how long:

  • Review requested · 2 d: a pull request waits for your review.
  • Checks failing or 3 unresolved comments: your own pull request needs work.
  • Due tomorrow, Overdue · 3 d, Bug, To do, In progress: a Jira ticket assigned to you.
  • Approve command: a session waits for you.
  • No reply · 48 min: someone named you in Slack or Discord, or sent you a Slack DM, and you haven't answered.

On a row:

  • + adds the item to the composer as context: a ticket, a pull request, or a message's whole thread.
  • Fix failing checks or Fix review comments starts the agent on your pull request's own branch, in one press.
  • Review with Claude, on a review request, starts a review of that pull request. See Review a pull request.
  • Fix this, on a Slack or Discord message, makes a ticket from it and starts a Build. See Slack and Discord.
  • A ticket's title opens its details, a pull request's opens it on GitHub, and a message's opens it in Slack or Discord.

Sort with Newest first or Longest wait first, search, and filter by reason, project, status, type or repository. Choose what counts as needing you in Settings › Inbox rules.

Sync

Orynx syncs Jira, GitHub, Slack and Discord every 2 minutes. The page bar says when it last did; press Sync to sync now, or Sync activity to see each tool's last sync and fix one that needs reconnecting.

When the agent is waiting

If a session needs your approval, a banner on Home says Claude is waiting for your approval and what it wants to do. If Claude asked a question, it says Claude is waiting for your answer and what it asks. Press Review to open the session.

Start a task

Everything starts in the composer on Home. Press ⌥⌘N anywhere to jump to it.

  1. Pick Build (Claude works on a branch in its own worktree) or Ask (Claude answers and changes nothing).
  2. Describe the task, or paste a Jira key like PROJ-1423, a GitHub pull request link, or a Slack or Discord message link: it turns into a chip. With a ticket added, the ticket is the brief, and the box can stay empty.
  3. Check the Repository. Orynx picks it from the ticket, and you can change it.
  4. Press Send to Claude (Send to Codex when a Codex model is picked), or Enter. The session opens.

Add context

The + button tells Claude what to work from:

  • Git repository: the folder Claude works in.
  • Ticket: a Jira or Orynx ticket, by key or title. Claude gets its description, comments and linked issues.
  • Pull request: by repository, number or title. Claude gets its diff, failing checks and review comments.
  • File: any file on your machine. Claude reads it where it is. Files that look like secrets, such as id_rsa, are refused.
  • Slack or Discord thread: from the messages waiting on you, or paste any message's link. Claude gets the whole thread: who said what, oldest first.

Remove a chip with its ×. Past two chips, +N shows them all.

Agent, model and effort

The agent picker shows the agent's state and lets you choose the model for this task, and an Effort from Low up to what that model takes. It lists Claude's models, then Codex's, each under its agent's name, as each agent offers them today. An agent that isn't signed in has none. Picking a Codex model runs the task on Codex: see Claude or Codex.

Skills

Type / in the composer to pick a skill: yours from Settings › Skills (tagged Orynx), your own Claude Code skills from ~/.claude (tagged Yours), or the repository's .claude/skills. Up to 5 per task.

Limits. Up to three sessions work at once. If a ticket already has a session, Orynx offers Open session or Start a new session.

Claude or Codex

Orynx runs a session on Claude or on Codex. Pick a model from either in the composer's agent picker, and Build, Ask, Fix and Review all start on that agent. If the agent you picked signs out, the picker falls back to the other one.

  • A session keeps its agent. Follow-ups, the pull request's title and description, the commit message and replies to reviewers all go to it. Its follow-up box offers only that agent's models.
  • The words name it. A Codex session says Codex wherever this guide says Claude: Codex wants to run a command, Message Codex, the Codex tab in the terminal.
  • The same rules. The rows in Settings › Coding agent decide Codex's edits and commands, with the same Allow once, Always allow and Deny. Codex reads code by running commands such as cat, rg or git diff; a plain read inside the worktree doesn't ask.
  • Codex stays in its sandbox. Its commands run with no network and write only to the worktree, even when a row allows the network. When Codex asks for more room, the Commands outside the sandbox row decides, and the command runs in Codex's wider sandbox, still away from Orynx's own files.
  • Codex's own rules count too. Commands you allowed in ~/.codex/rules run without asking Orynx. They still run in the sandbox and show as steps.
  • No questions from Codex. Only Claude asks you questions in a session. When Codex needs a decision, it asks in its summary, and you answer with a follow-up.
  • Cost. Codex gives no price, so a Codex session shows its time and turns only.

The tickets board

Tickets shows your sprint as a board or a list. Pick the project and sprint in the page bar, and switch between Board and List at its end.

  • Columns: To do, In progress, In review and Done.
  • Filters: search, Source (Jira or Orynx), Assignee, and under Filters: status, type, priority and due date.
  • A card shows the key, type, title, priority and due date. Click its title for the full ticket, with Open in Jira and Add to composer.

Hand a ticket to the agent

Press Ship on a card. Orynx adds the ticket to the composer on Home; add anything else, then press Send to Claude. To start several, tick their checkboxes and press Ship all.

Once a ticket has a session, its card shows the agent's state and links to the session:

Needs you The agent waits for your approval or your answer.
Working The agent is on it.
Done, ready for PR Finished. Create the pull request when you are happy.
Done, ready to push Finished on a ticket that already has a pull request.
PR open · PR merged · PR closed Where the pull request stands on GitHub.
Stopped You or the agent stopped the session.

New tickets

Press New in the page bar, or + on a column to start the ticket in that column. Fill it in and press Create ticket. Save in picks where it goes:

  • Jira · PROJ, while the board shows a Jira project: Orynx makes the issue in that project, with the project's own types and priorities, assigns it to you, adds it to the sprint on screen and moves it to the column you started from. If Jira refuses, the dialog shows Jira's reason and keeps what you typed. If Jira makes the issue but can't add it to the sprint or move it, the dialog says so and links to it.
  • Orynx, for work that is not in Jira. An Orynx ticket (ORX-12) has a title, description, type, priority, status and due date. It is saved in Orynx on this machine and never added to Jira. Without Jira connected, the board shows only Orynx tickets.

Claude can list, create and update Orynx tickets during a session. Deleting one always asks you first.

Search

Press ⌘K (Ctrl+K on Linux), or Search at the top of the sidebar. Find a ticket by key or title, a pull request by number or repository, or a session.

  • A ticket opens its details, a session opens its page, and a pull request opens on GitHub.
  • Search covers what Orynx has synced: your sprint and assigned Jira issues, Orynx tickets, your open pull requests and those waiting for your review, and every session.

Work in a session

A session is one task for your agent. In Build, it gets its own git worktree under ~/.devhub/worktrees, so your own checkout stays untouched. The branch is made at Claude's first edit and named after the ticket, like feat/PROJ-1423, following your repository's style. An Ask session reads the folder in place and changes nothing. This section says Claude; a Codex session reads the same in Codex's name (see Claude or Codex).

Follow along

  • The stepper beside the title shows where Claude is: Plan, Build, Test, Review, Pull request. For a question or a run, Claude names its own steps.
  • What agent did groups everything under the stepper's steps, each with how long it took, and shows the session's time, turns and cost. The step Claude is on starts open; press any step to open it in place, or Expand all. Inside are the files read and edited, each command, and Claude's to-do list, with a tick for what's done, a shimmer on what it's doing and an empty dot for what's to come. The running step's title shimmers, and a command step turns red when one of its commands failed. Open Sent Claude the brief to see exactly what Claude was sent.
  • Changes shows the live diff, file by file, with a Viewed box on each and Wrap lines for long lines.
  • Ports lists the servers Claude or you started in this session, with Open, Restart and Stop.
  • Context shows the ticket and everything else Claude was given.

Each pane has a Full screen button.

Approve or deny

When Claude needs your permission, it stops and asks: Claude wants to run a command, edit a file, start a server, or change a Jira issue. Your answer:

  • Allow once: this time only.
  • Always allow: adds the command to your allowed commands, or allows servers in this repository, so Claude stops asking.
  • Deny: Claude does not do it and carries on.

You can answer from the session, the banner on Home, a notification, or your phone. What Claude may do without asking is set in Settings › Coding agent.

Answer Claude's questions

When Claude needs a decision the code, the brief and the repository's rules don't answer, it stops and asks: Claude has a question, and the session reads Needs your answer. Each question shows its choices as cards:

  • Pick a choice, or several when the question takes more than one.
  • Other opens a box for your own answer.
  • Send answer sends your picks, and Claude carries on with them.
  • Skip lets Claude carry on with its best judgement. It says in its summary what it assumed.

A question asks you whatever level you picked in Settings, and has no Always allow. Once sent, an answer can't be changed: correct Claude with a follow-up. Home's banner and the bell tell you a question is waiting; answer it in the session. Codex doesn't ask questions this way.

Steer with follow-ups

Use Message Claude at the bottom of the session to ask for a change. Claude carries on in the same worktree with everything it already knows; there is no need to start over. Its + adds more context, as the composer's does.

Terminal and editor

  • Press ⌃`, or More actions › Terminal, for the terminal. The Claude tab shows the commands Claude ran; add your own shell in the session's worktree with New terminal.
  • More actions › Open in VS Code (or Cursor, chosen in Settings › Coding agent) opens the worktree in your editor.

Manage sessions

Recent sessions sit in the sidebar; View all lists every one, with search and filters. Each session's ⋯ menu has Stop, Rename, Pin, Copy link and Delete. Deleting removes the worktree too, and can also delete the branch. Changes that were not pushed are lost.

Ship the pull request

When Claude finishes, the session says Ready for a pull request, with the files and lines it changed. Nothing leaves your machine until you create it.

  1. Review the diff in Changes. Ask for anything else with a follow-up.
  2. Press Create pull request. Claude drafts the title and description; edit them as you like.
  3. Press Create pull request in the dialog. Orynx pushes the branch and opens the pull request on GitHub, and the page bar shows Open PR #2841.

If you ask for more changes later, the session says Ready to push: press Push to PR #2841, check the commit message Claude drafted, and push.

Prefer Claude to do this on its own? Set Push the branch and Open a pull request to Allow, or pick Hands-off, in Settings › Coding agent.

Answer your reviewers

When reviewers leave comments, press Fix review comments on the pull request's row on Home, or ask for the fixes with a follow-up. Once they are pushed, press Reply to reviewers, in the page bar while the pull request is open:

  1. Orynx lists the pull request's unresolved review threads. Claude drafts a reply for each one its changes address, with Resolve ticked; the others start empty.
  2. Edit any reply, and tick or untick Resolve.
  3. Press Post replies. It is the only press that writes: the replies go out as you, and the ticked threads are resolved. A thread left empty and unticked stays as it is.

After the merge

Orynx checks each open pull request at every sync. Once it's merged, the session reads PR merged, and when nothing would be lost, Orynx removes the worktree and keeps the branch. A closed pull request keeps its worktree. To free disk space on a schedule, pick Delete old sessions in Settings › Coding agent.

If the session was sent a Slack or Discord thread, Orynx also offers to tell the thread once the pull request opens: see Slack and Discord.

Review a pull request

A review request on Home has Review with Claude in place of +. One press starts a review session and opens it. It is read-only, like an Ask: Claude reads the pull request's code in its own worktree, from the folder in Settings › Repositories that holds that repository. Without one, Claude reviews from GitHub's diff alone.

  1. Claude leaves comments under lines of the diff in Changes, at most 20. The file list counts each file's comments.
  2. Each comment has Keep, ticked, and Edit. Untick Keep to leave one out.
  3. When Claude is done, the bar says how many it left, such as Claude left 3 comments. Press Post review.
  4. The dialog holds Claude's summary, Your verdict (Comment, Approve or Request changes) with what Claude would pick, and how many comments will be posted. Its Post review posts one review, as you.

Nothing reaches GitHub until that last press. Ask Claude to look again with a follow-up; new comments go out as another review. If the author pushed after Claude read the pull request, the dialog says so, and the comments go on the commit Claude read. To review again after a push, press Review with Claude and pick Start a new session.

Slack and Discord

Once Slack or Discord is connected, Home lists the people waiting on your reply, beside your tickets and pull requests.

Who is waiting on you

  • A message counts when someone names you, or sends you a Slack DM, and nothing of yours comes after it. Mentions of @here or a group, and messages from bots, don't count. Orynx looks back 7 days.
  • It shows once it has waited longer than Wait before a message counts in Settings › Inbox rules: 30 min, 1 h, 2 h (the default), 4 h or 1 day. Each tool has its own rule there to turn it off.
  • Past the wait, Orynx tells you once that they are waiting on your reply. Its row in Settings › Notifications is Someone is waiting on your reply.

Hand a thread to the agent

  • Press + on the message's row, pick Slack or Discord thread under the composer's +, or paste any message's link into the composer. The thread becomes a chip like Neha K. in #checkout, and Claude gets the whole thread, oldest first.
  • Fix this on a row opens New ticket, filled in as a Bug with who reported it, where, and the link. It goes to the Jira project of the composer's folder, in its active sprint, or to Orynx. Once the ticket is made, a Build starts on it with the thread as context, and opens.

Tell the thread

Once the session's pull request is open, a session that was sent a thread offers Tell the thread: a reply with the pull request's link, ready to edit. Post reply posts it in the first thread the session was sent, in Slack as you and in Discord as your bot. Not now puts it away for that session. Nothing else is ever written to Slack or Discord.

Notifications

Orynx tells you when the agent waits for your approval or your answer, when a session finishes, and when someone requests your review, your checks fail, a ticket is assigned to you or a Slack or Discord message waits past your wait time.

  • The bell at the bottom of the sidebar keeps every notification, with a Needs you tab and Mark all read.
  • Pop-ups appear in the corner, up to three. An approval stays until you answer it; for a command, press Allow once right there. A question says Claude has a question, with Review to open the session.
  • Desktop notifications and sounds reach you while you work elsewhere. Turn them on in Settings › Notifications.

Settings › Notifications also sets what you hear about, and Do not disturb: pause for an hour, until tomorrow, or until you turn it back on. Quiet hours (19:00–09:00 on weekdays, by default) still let approvals through. Send a test notification shows how it looks.

Use it from your phone

Any phone or other machine on the same wifi can open Orynx at https://orynx.local. Your code and tokens stay on the machine that runs it.

  1. On the other device, open https://orynx.local.
  2. Enter the Orynx password you chose at setup. A cookie keeps the device signed in for a year.
  3. Trust the Orynx certificate once, so the browser stops warning and lets you install the app (below).

Trust the certificate once

The certificate comes from a certificate authority made on your machine. On the device, open http://orynx.local/orynx-ca.crt, then:

  • iPhone or iPad: Settings › General › VPN & Device Management › install the Orynx profile, then Settings › General › About › Certificate Trust Settings › turn on Orynx local CA.
  • Android: Settings › Security › Encryption & credentials › Install a certificate › CA certificate, and pick the file.
  • Mac: open the file to add it to the System keychain, then in Keychain Access open it › Trust › Always Trust.
  • Windows: open the file › Install Certificate › Local Machine › Trusted Root Certification Authorities.
  • Linux: copy it to /usr/local/share/ca-certificates/ and run sudo update-ca-certificates. Chrome and Firefox may want it imported in their own settings too.

The certificate authority can sign only for orynx.local and localhost, so trusting it lets nobody pose as any other site.

Safe on a shared wifi

  • Orynx itself listens only on 127.0.0.1. The wifi reaches it through a front door on ports 443 and 80 that answers only the name orynx.local.
  • A device sees nothing of Orynx until it enters your password. Whoever has the password can use Orynx as you, Claude's sessions included, so pick one you use nowhere else.
  • After 10 wrong passwords in 15 minutes, from any device, Orynx stops checking until the oldest is 15 minutes old.
  • Everything goes over https. http://orynx.local only hands out the certificate and redirects.

Keep it as an app

Orynx installs from the browser as an app, with its own window and icon:

  • Chrome or Edge: the install icon at the end of the address bar, or ⋮ › Cast, save and share › Install page as app.
  • Safari on a Mac: File › Add to Dock.
  • iPhone or iPad: Share › Add to Home Screen.
  • Android: Chrome's ⋮ › Add to Home screen.

The desktop app

Orynx also comes as a desktop app, from GitHub releases: a .dmg for Apple silicon Macs and an .AppImage for Linux. It runs Orynx itself, with no install script, and stays on this machine: for orynx.local on your phone, install with ./install.sh.

  • macOS: open the .dmg and drag Orynx to Applications. The first open says macOS can't check it: System Settings › Privacy & Security › Open Anyway, once per install.
  • Linux: chmod +x the AppImage and open it. It needs FUSE 2 (libfuse2), and sessions run commands only with bubblewrap and socat installed.

The desktop app updates itself from Settings › About: press Restart to update.

Update and uninstall

Update

Press Update in Settings › About, or run git pull && ./install.sh in the clone. An Orynx installed before Update was there needs ./install.sh run once more by hand first.

Forgot the password, or sign every device out

Delete ~/.devhub/password and restart Orynx. Setup opens again on this machine, with your profile filled in, and every other device must sign in with the new password. 

# macOS
launchctl kickstart -k gui/$(id -u)/dev.orynx.server
# Linux
systemctl --user restart orynx

Uninstall

macOS:

launchctl bootout gui/$(id -u)/dev.orynx.server
rm ~/Library/LaunchAgents/dev.orynx.server.plist
sudo security remove-trusted-cert -d ~/.devhub/tls/ca.crt

Linux:

systemctl --user disable --now orynx && rm ~/.config/systemd/user/orynx.service
sudo rm /usr/local/share/ca-certificates/orynx-local-ca.crt /etc/sysctl.d/60-orynx.conf
sudo update-ca-certificates

Your settings, cache and certificate stay in ~/.devhub until you delete it.

Troubleshooting

The page says "Orynx restarted"

The server makes a new session token every time it starts. Reload the page.

Settings says "Can't reach your-team.atlassian.net"

Check the VPN first. UNABLE_TO_GET_ISSUER_CERT_LOCALLY in the log means a proxy on your network re-signs TLS with a root your OS does not trust.

Settings says "Orynx can't find the gh command"

Orynx looks for gh on the PATH of the terminal that started it. Run which gh there, or connect GitHub with a personal access token instead.

Settings says Codex is "Not installed"

Orynx looks for codex on the PATH of the terminal that started it (the desktop app uses your login shell's), and needs version 0.166 or later. Run codex --version there; an older Codex counts as not installed.

./install.sh says Orynx didn't answer

Read ~/.devhub/orynx.log on macOS, or journalctl --user -u orynx on Linux. "can't listen on port 443" or "80" means another web server holds it. A pnpm start left running holds 4317.

Another device can't open orynx.local

Check it is on the same wifi: guest and office networks often keep devices from seeing each other. Android finds .local names from Android 12. A second machine running Orynx on the same wifi can't take the name; its log says so.
