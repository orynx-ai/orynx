Know what needs you, and why.

Orynx reads your assigned tickets, review requests and your own pull requests, then shows only what is waiting on you. Each row says why it is there and how long it has waited, so the next step is obvious.

  • Approve command

  • Review requested · 4 h

  • Checks failing

  • Due tomorrow

Board or list, filtered by assignee, status, type, priority and due date. Every card shows where its Claude session stands, and any card can start one.

How it works

Delegate the work. Stay close to the change.

A session takes a ticket from brief to pull request in five visible steps: plan, build, test, review and pull request. Step in at any of them, or let it run.

  1. Start from a ticket or a sentence

    Paste a Jira key, pick a ticket from the board, or describe the task. Add pull requests and files as context, then choose the repository and the model.

  2. Claude works in its own worktree

    Each session gets a fresh git worktree and branch, so your main checkout stays untouched. Watch the plan, the files Claude reads and every edit as it happens.

  3. Your settings decide what runs

    Claude does what you allowed in Settings and asks for the rest: allow once, always allow, or deny. Review the diff file by file and ask for changes without starting over.

  4. Ship your way

    Claude drafts the pull request title and description. Push and open it with one click, or allow Claude to push the branch and open the pull request on its own.

Your rules

As hands-on or hands-off as you like.

Pick a level in Settings › Coding agent, then set any kind of call to Allow, Ask or Block. Claude checks your settings before every call.

  • Three levels to start from. Cautious asks before every edit and command. Balanced edits freely and runs your allowed commands. Hands-off runs, pushes and opens pull requests by itself.
  • Your own mix. Edits, commands, the network, deleting outside the session's copy, pushing and pull requests each have their own row.
  • Pull requests without the click. Allow push and pull request, and Claude ships the session's branch as you, never forced. Until then, it never pushes on its own.
  • Sandboxed unless you say so. Commands run with no network and write only to the session's copy. Each risky row warns you when you allow it.
  • Stop at any moment. Stop Claude mid-step, or discard the session and its worktree.

Local-first

Your workspace. On your machine.

There is no Orynx cloud. Orynx is a small server and a web app, both on your laptop.

  • Tokens in your OS keychain

    Jira and GitHub tokens are saved in your keychain and never reach the browser.

  • Bound to 127.0.0.1

    The server listens only on this computer and checks a token on every request.

  • A local cache

    Synced tickets and pull requests live in one file on your disk.

  • Only what you connect

    Orynx talks only to the services you connect: Jira, GitHub and Claude today, Slack and more next.

Get started

Running in a few minutes.

From a copy of the Orynx repository, on macOS or Linux:

  • Node 24 and pnpm 10
  • Claude Code, signed in on this computer
  • A Jira Cloud API token, and GitHub through the gh CLI or a token

Then connect Jira and GitHub in Settings, add a repository, and start your first session from Home.

FAQ

Questions, answered.

Does my code leave my computer?

Orynx itself has no cloud. Claude reads the files a task needs in the session's worktree through your own Claude login, exactly as Claude Code does in your terminal. Jira and GitHub are called with your own tokens.

Which Claude account does it use?

The login Claude Code already has on your computer, through the Claude Agent SDK: a company claude.ai account, an API key, Amazon Bedrock or Google Vertex. Orynx needs no key of its own.

Can Claude push code or open a pull request by itself?

If you allow it. A fresh Orynx never pushes. In Settings › Coding agent, pick Hands-off, or set Push the branch and Open a pull request to Allow, and Claude pushes the session's branch and opens the pull request on its own. Set them to Ask to click for each one, or Block to keep them off.

Does it change my working copy?

No. Every session works in its own git worktree on its own branch. Your main checkout, and anything uncommitted in it, stays as it was.

Which connectors come next?

Slack mentions and direct messages are next. Reading them needs a Slack app your workspace admin approves, so the timing depends on that approval. More connectors follow, each a small adapter on the local server, so a new tool lands in the same inbox.

Does it work with agents other than Claude?

Claude today. Other agents can plug in later through one small adapter.
