# Trace steps: a running shimmer, steps that open in place, and failed and to-come steps

Status: approved
Roadmap: not on the roadmap. This is the user's ask from 22 Oct 2026, about shadcn's Trace (https://ui.shadcn.com/docs/components/base/trace). First "can we integrate [it] in session page where claude shows progress?", then, once told that `ActivityStep` already comes from it without three of its parts: "can we have all three?" The spec takes 046, the next free number after 045. The branch is `feat/046-019-trace-steps-and-jira-ticket`, made from `origin/main` at `edc8ad7`, shared with spec 019 (the user's ask, 2 Nov 2026: "in one session and one pull request").

## Assumptions

Correct these now, or the work goes ahead on them.

- **Trace's parts go into our own `ActivityStep`. We don't install shadcn's `trace`.** The linked page is the Base UI version. This repo is on Radix (`radix-ui`, style `new-york`), and `shadcn add trace` would bring `@base-ui/react`, a dependency `docs/architecture.md` doesn't list. So `ActivityStep` gets the three parts it left out in spec 006, using Radix `Collapsible` from `radix-ui` as `HistoryRow` already does. No new dependency.
- **Only Claude's progress on the Session screen changes.** It's the only place that uses `ActivityStep`. The sidebar, the Stepper and Sync activity stay as they are.
- **1. A shimmer on the running step's title (Q2).**
  - A step shimmers when the server sends it with `state: 'running'` and it isn't waiting for you. "Reading your ask…", "Exploring the code" and "Running a command" shimmer. "Wants to run npm test" keeps its amber dot and stays still, because Claude isn't working, it's waiting for you.
  - The title keeps its size, weight and words, so nothing moves when the shimmer starts or stops.
  - When your computer is set to reduce motion, the title is plain text in its usual colour. It never freezes halfway through the band.
  - A screen reader hears nothing new: a running step's title is already in the present tense ("Exploring the code") and a done one in the past.
- **2. Steps that open in place (Q3).**
  - A step that opens today (`hasDetails`) gets a chevron at the end of its title, pointing right. Pressing the title, or Enter or Space on it, opens the details under the step and turns the chevron down. Pressing it again closes them. That replaces the `StepDetails` dialog.
  - Only the title is the button. The detail line under it stays outside the button, so a link in it (a pull request's number, a link in Claude's summary) still works.
  - What opens is what the dialog shows today: the brief as Markdown, with its loading and error states; every file Claude read or edited, each with its copy button, an edited one opening its diff in the Changes tab; Claude's to-do list; each command as code; and your whole message.
  - The Finished step stops opening, because its summary already shows in full under its title.
  - Every step starts closed. Several can be open at once. An open step stays open while the session updates, so a running command step shows each new command as it comes. Orynx forgets which steps were open when you leave the page or reload it.
  - Opening a step never scrolls the page. Following Claude's progress keeps its rule from spec 013: it follows while the pane's end is in view.
- **3. Failed and to-come steps (Q4, Q5).**
  - **Failed (`error`)** looks like done, in red: a `danger-subtle` dot with a `danger` × (`Cancel01Icon`). A screen reader hears ", failed".
  - A command step is failed when one of its commands ended with an error. The server already records each command's result for the Terminal's Claude tab (`logEnd`'s `failed`, spec 036). The command step keeps the same fact for each of its commands. While the step is running it shimmers as usual. It turns red once it's done.
  - Refused, denied, stopped and interrupted steps keep their plain dot (Q4).
  - **To come (`pending`)** is an outlined dot (1 px `border-control`, no fill, like the Stepper's to-do step) with the words in `text-muted-foreground`. A screen reader hears ", to come".
  - It shows on Claude's to-do list when the plan step is open. Each item is a line: a green tick when Claude has done it, its words shimmering while Claude is on it, and the outlined dot while it's still to come (Q5). To do that, the server keeps each to-do's `status` (`pending`, `in_progress`, `completed`) from Claude's `TodoWrite` call. Today it keeps only the words.
- **The contracts change, and older sessions still read.** `@devhub/contracts` gets each command's result on the command step and each to-do's status on the plan step, both optional. A session saved before this spec reads as it does today: its command steps show no failures, and its to-do items show without marks.
- **Looks use only existing tokens:** `success`, `success-subtle`, `danger`, `danger-subtle`, `border-control`, `text-primary` and `text-secondary`. The shimmer's 2 s loop is the one new motion value (Q2).

## Goal

When Claude is working, I can see which step it's on because its title shimmers. I can open a step right where it is to see its files, commands or plan, without a dialog covering the page. A command that failed shows in red, and Claude's to-do list shows what's done, what it's doing and what's still to come.

## Out of scope

- Installing shadcn's `trace` as it is, Base UI, or any new dependency.
- How long each step took, or counts beside its title (Trace's `TraceDescription`).
- A command's output inside the open step. It stays in the Terminal's Claude tab, unless Q6 says otherwise.
- Red for an edit, a ticket tool or a Jira call that failed. Only commands can fail in this spec.
- Remembering which steps were open after you leave the page, and Open all or Close all.
- The shimmer anywhere else: the sidebar, the Stepper, Sync activity or the Terminal.
- New Stepper states, such as stopped or failed.
