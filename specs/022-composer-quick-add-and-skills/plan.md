# Plan: Composer quick add and skills

Spec: `specs/022-composer-quick-add-and-skills/spec.md`

## Order of work

The parts go in an order where each one stands on what's already built and can be tried in the browser on its own. Skills (G) come last, as Q1 said.

1. **A. Several chips** (tasks 1–2). The contract's limits and the server's "first ticket is the session's" come first, because every later part adds chips through them. Then the composer's own rules: no more replacing a ticket, the new limits, the placeholder for several tickets.
2. **C. The strip and the context dialog** (tasks 3–5). As soon as more than two chips can exist, the composer needs +N. The +N chip is a `@devhub/ui` part (`ContextMore`) with its stories, then the strip, then the dialog with its tabs.
3. **F. The ticket dialog** (tasks 6–9). Server first: the Jira client reads the fields Q8 lists, a ticket service answers `GET /api/tickets/:key`, the api-client parses it. Then the dialog itself, opened from a small store and drawn once in the shell, so Home, Tickets and ⌘K all open the same one and it outlives the ⌘K dialog. It comes before D and E because both replace a title's Jira link with it.
4. **D. One action on Home's rows** (tasks 10–11). The ui change (one action's width, a title with no arrow) and then Home's + toggle, the Jira title opening the dialog, and the pull request title without its arrow.
5. **E. Ship adds to the composer** (tasks 12–13). Ship becomes "add the chip, open Home, focus the box"; its folder menu and start go. The e2e flows that started sessions by Ship move to the composer in the next task, since they'd fail otherwise.
6. **B. Files by path** (tasks 14–18). The file picker on the server (020's folder picker, taught to pick files), the typed-path check, then the contract's file chip by path, the server's check at Send and the brief, and the tool decision that lets Claude read exactly those files. Then the api-client and the composer.
7. **G. Skills** (tasks 19–24). `yaml` and the skills reader on the server, the route, the brief's skills and the folders Claude may read, then the api-client, the `SuggestionList` part and the composer's `/` list.
8. **Docs, the browser and review** (tasks 25–27). Learn pages, the design map, the roadmap line, the user's script for `docs/product/spec.md`, a real browser at 360 and 1280 px in both themes, then `/review`.
