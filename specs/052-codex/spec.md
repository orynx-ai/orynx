# Codex: run a session on OpenAI's Codex, beside Claude

Status: approved
Roadmap: not on the roadmap. This is the user's ask from 3 Nov 2026: "lets add support for codex". The product spec leaves room for it: Settings › Coding agent is "Which agent (Claude now, more later)", the agent adapter exists "so other agents can follow later without changing the screens", and `settings.html` keeps a "More agents" card for it. The spec takes 052 because another session is drafting 051 (`feat/051-claude-asks`) in the main clone. The branch is `feat/052-codex`, made from `origin/main` at `75cf88fe`, in the worktree `orynx-052`.

## Assumptions

Correct these now, or the work goes ahead on them.

**A. Finding and checking Codex**

- Orynx runs the Codex CLI already on this computer: `codex` on `PATH`, or the program `DEVHUB_CODEX` names. Orynx doesn't ship Codex, because its macOS program is 363 MB, about 70 times the Agent SDK (Q1). Codex 0.166 or later is required, and an older one counts as not installed.
- Orynx only checks Codex's own login, as spec 010 checks Claude's. The login is a ChatGPT sign-in or an API key, kept by Codex in `~/.codex`. Orynx reads it through `codex app-server`'s account read, which needs no prompt and uses no quota. Orynx never signs in for you and never keeps an OpenAI key.
- In Settings › Coding agent, the "More agents" card becomes a **Codex** card, drawn as the Claude card is, with **Check again**. It has four states (wording in Q5):
  - Signed in: "Signed in with ChatGPT as <email>", or "Signed in with an API key"
  - Not signed in: "Run `codex login` in a terminal, then check again."
  - Not installed: "Install Codex with `npm install -g @openai/codex`, then check again."
  - Error: "Couldn't check Codex. Check again."
- Today `/api/status` has one agent, `{ id: 'claude', connected }`. It now lists both agents with whether each is signed in, and the composer asks for an agent's models only while that agent is signed in.
- Someone who never installs Codex sees only the new card, and nothing else changes for them.

**B. Picking Codex**

- The composer's agent picker lists Claude's models, then Codex's, each group under its agent's name, and each model with its effort levels. An agent that isn't signed in has no group (Q2).
- The pick is kept in this browser with the model and effort, as they are today (`devhub.home`), and the session's follow-up box shares it. Build, Ask, Fix this and Review with Claude all start on it.
- When the picked agent signs out, the picker falls back to the other agent's default, as it drops a model that's no longer listed today. With neither signed in, it reads as it does now when Claude is signed out.
- Codex's effort levels `low`, `medium`, `high` and `xhigh` keep Orynx's names. Codex's `minimal` isn't offered, and Claude's `max` stays Claude's.
- A session keeps its agent for life. Follow-ups, Orynx reading the ask (spec 042), the pull request's draft and commit message (spec 014), review replies (spec 049) and the review (spec 050) all go to it. `session.json` saves `agent` beside the agent's own session id, and a session saved before this spec reads as Claude.
- Starting on an agent that isn't signed in is refused as it is today for Claude, with that agent's name.

**C. A Codex session**

- It gets the same brief, instructions, worktree and Settings rows as a Claude session. Where the brief tells Claude to read `CLAUDE.md`, Codex is told to read `AGENTS.md` and `CLAUDE.md`.
- Orynx runs one `codex app-server` per session over stdio, in the worktree, and speaks its JSON-RPC protocol through zod schemas of its own. It doesn't use the Codex SDK, which runs `codex exec` and can't ask before a command (Q1). No npm dependency is added.
- Codex's own settings are left out, as Claude's are (spec 011, Q7). Orynx starts Codex with the MCP servers, hooks, profiles, approval rules and sandbox settings of `~/.codex/config.toml` overridden. Only its login and model provider stay. Codex still reads the repository's `AGENTS.md` itself (Q3). One thing can't be overridden: the command rules you saved in Codex's own `~/.codex/rules/` still let their commands run without Orynx asking. They run inside the sandbox all the same, and show as steps (changed while planning, 3 Nov 2026).
- Orynx's own tools reach Codex as its dynamic tools (`thread/start`'s `dynamicTools`), answered in Orynx's own process as Claude's are. They are tickets (spec 037), steps and servers (spec 042), Jira (spec 044) and review comments (spec 050). Codex gets no MCP server at all. Each tool asks, runs or is refused as it does for Claude (changed while planning, 3 Nov 2026).
- Commands run in Codex's own sandbox: Seatbelt on macOS and Landlock on Linux. It writes only in the worktree and the temporary folder, has no network, and reads nothing under `DEVHUB_HOME` but the worktree, as Claude's does (spec 012).
- Every command Codex wants comes to Orynx's command decision first, with the same rows, allow list and approval callout as Claude's. Unlike Claude's, a Codex command never leaves the sandbox. While the sandbox hides `DEVHUB_HOME`, Codex keeps even an allowed escalation inside it, with `DEVHUB_HOME` still hidden. So a command the network or deleting-outside row allows runs in the sandbox, and fails there if it needs the network. When Codex itself asks for more than the sandbox gives, the Commands outside the sandbox row decides, and the command runs in Codex's wider sandbox. When the sandbox can't run, the session gets no commands, as Claude's does (spec 012, Q2b; Q6) (changed while planning, 3 Nov 2026).
- Every edit Codex makes comes to Orynx first. Inside the worktree, the Edit files row decides: the edit goes ahead, or with Ask first, it waits in the callout with its diff. An edit outside the worktree is refused. Pushes and pull requests follow their rows, as Claude's do.
- Codex's work maps onto the steps Claude's does: reads and searches, its plan (to-do list), edits, commands with their output, Orynx tool calls, and its last message as the summary. Its reasoning isn't shown, as Claude's thinking isn't.
- A follow-up sent while Codex works goes into its current turn through `turn/steer`, as Claude reads one after its current step (spec 013, AC-12). After Done or Stop, it resumes Codex's thread. Stop interrupts the turn, then ends the program 5 seconds later if it hasn't ended (changed while planning, 3 Nov 2026).
- The usage line (spec 047) counts Codex's turns. Codex gives no price, so cost shows as it does when Claude doesn't say one.
- A session that stops with an error reads it the same way. Signed out is the login problem, a ChatGPT plan's usage limit is the limit problem, and a follow-up whose thread Codex no longer has is the resume problem.
- Codex gets the same environment allow list as Claude (`agent-environment.ts`), with `OPENAI_` and `CODEX_` variables in place of `CLAUDE_` and `ANTHROPIC_` ones, and its analytics turned off. Neither agent gets the other's variables.

**D. Words**

- About 119 lines in 25 app files name Claude, spread over each feature's `*-words.ts` (Q4). On 27 Oct the user chose "the agent, not Claude by name" for the progress heading, and Stop already says only Stop.
- Words about one session name its agent: "Codex wants to run a command", "Message Codex", "You stopped Codex", "Codex left 6 comments", the Codex terminal tab and its notifications.
- The composer's words name the picked agent: "Send to Codex", "Ask Codex about your code…", "Review with Codex".
- Settings words that cover both agents say "the agent": "What the agent can do without asking", and "Anything the agent downloads runs on your computer."
- Claude's own card, its login check and Orynx's name don't change.
- What a Codex session writes to GitHub doesn't say Claude. The commit message's `Co-Authored-By: Claude` line and the pull request's "Claude's summaries" heading name the session's agent (Q8).

## Goal

Some of us use Codex, not Claude. Pick a Codex model in the composer and the session runs on Codex: in its own worktree, inside a sandbox, asking before anything risky as Settings › Coding agent says, with the same steps, approvals, changes and pull request a Claude session has.

## Out of scope

- Shipping Codex with Orynx or installing it for you (Q1).
- Signing in to Codex or OpenAI from Orynx, and a field for an OpenAI API key.
- A default agent in Settings, apart from the composer's pick (Q2).
- Changing a session's agent partway, and running Claude and Codex on one ticket side by side.
- Codex's cloud tasks, its web search tool, and images in the brief.
- Codex's own skills, plugins and MCP servers from `~/.codex`. Skills you add to the composer still go in the brief, as they do for Claude.
- Any other agent: Gemini, Cursor or Copilot.
- Windows, where Codex's sandbox differs. Orynx runs on macOS and Linux today.
