## Assumptions

Correct these now, or the work goes ahead on them.

- **Build order, and what this waits on.** On 2026-10-17 the user asked to start 007 while another session builds 006. This branch starts from `feat/005-settings-screens` (reviewed, not yet merged), because Home applies 005's inbox rules and shows 005's `SourceMark` logos. It moves onto `main` once 005 merges. The server half (cache, Jira and GitHub reads, rules, sync, endpoint, event, api-client) needs nothing from 006, so it's built first. The screen needs 006's `AttentionList` and `AttentionRow`, `Panel` and `Skeleton`, so its tasks come last and start only after 006 merges. This spec adds nothing to `@devhub/ui`. If a part is missing, it goes back to 006 or to a person.
- **Two sources now: Jira and GitHub.** Slack rows come with 016 (Q1a). The DevHub rule ("Claude sessions waiting for my approval") reads the session store that exists today. Nothing creates a session until 011, so that rule matches nothing yet. Its rows appear once 011 and 012 create sessions that wait.
- **What each rule reads.** One sync makes one Jira request and one GitHub request:
  - Jira: issues where you're the assignee and the status category isn't Done (`assignee = currentUser() AND statusCategory != Done`), at most 100. Statuses are matched by category, never by name.
  - GitHub, through its GraphQL API and the octokit client from spec 004 (no new dependency):
    - **Review requested:** open pull requests where your review is requested (which ones: Q3), at most 100.
    - **Checks failing:** your own open pull requests, at most 100, with the combined check state of each one's latest commit.
    - **Unresolved comments:** the review threads on those same pull requests that aren't resolved and whose last comment isn't yours.
- **The wait.** Each row has one moment its wait counts from, and the list puts the longest wait first (Q2):
  - Jira: when the issue entered its current status category (Jira's `statuscategorychangedate`), or when it was created if Jira doesn't say.
  - Review requested: when your review was last requested, or when the pull request was opened if GitHub doesn't say.
  - Checks failing: when the first failing check on the latest commit finished.
  - Unresolved comments: when the oldest of those threads got its last comment.
  - Session waiting: when the session last changed (`updatedAt`).
- **The cache.** It's `<DEVHUB_HOME>/cache.db`, written with better-sqlite3 and drizzle-orm. `docs/architecture.md` plans both for this spec. Both go into `@devhub/core` only, through `pnpm add`. It holds titles and metadata (keys, numbers, names, statuses, dates and links), never descriptions or comment text. Home always answers from the cache, so it opens at once even when Jira or GitHub is slow. A cache DevHub can't read, or one an older DevHub wrote, is deleted and filled again on the next sync. Disconnecting a tool removes its rows from the cache.
- **Rules apply when Home reads, not when DevHub syncs.** Turning a rule off or on in Settings › Inbox rules changes Home at once, in every open tab, without asking Jira or GitHub again.
- **Sync.** DevHub syncs once when it starts. After that it syncs every 2 minutes while at least one DevHub page is open, at once when you press Refresh, and at once when you connect a tool. Only one sync runs at a time: pressing Refresh during a sync waits for that one to finish. A tool that fails keeps its last rows and says so (Q5). The other tool's rows still update.
- **One row per ticket or pull request** (Q4). A pull request that fails checks and also has unresolved comments shows once.
- **The tab lives in the address.** Jira is `/?inbox=jira`, Pull requests is `/?inbox=pull-requests`, and All has no parameter. A reload stays on the tab, and 015's quick start "Review a pull request" can link to it. Each tab shows its count, and All's count is the total.
- **A session-waiting row goes in its ticket's tab.** When the session works on a ticket, the row shows the Jira mark and counts under Jira, as the design draws it. When it works on a pull request, it counts under Pull requests. With neither, it shows only in All.
- **Links.** Jira and GitHub links open in a new tab. A session row opens the session inside DevHub. The title and the action go to the same place (006 AC-18).
- **The sidebar's Home count** (Q1b) is the number of rows in All, drawn as the design system's `.dh-nav-count`. It hides at 0. The Tickets count waits for 008.
- **Pages of 16** (amended by Q9c). The list holds at most 300 rows (100 from each read), so at most 19 pages. Everything happens in the browser: search, filters, order and pages work on the rows the page already has, with no new request.
- **Search, filters and order** (amended 17 Oct 2026, Q9 and Q10). Each tab has a toolbar under the tabs: a search box on the left and the tab's filters on the right. All filters by Reason; Jira by Reason, Project and Status; Pull requests by Reason and Repository. The list shows the newest wait first, and a menu in the panel's head switches to the longest wait first. Search, filters, order and page live in the address, like the tab.
- **"Synced 2 min ago"** counts from the last sync in which every connected tool answered. It moves on by itself each minute. Under 768 px it hides, as the design system says for page bar meta.

## Goal

When I open DevHub I want one list of the Jira tickets and pull requests waiting on me. Each one says why it's there and how long it has waited, with the longest wait first and the one thing to do next. The list keeps itself up to date while I work, and it opens at once because DevHub remembers the last one.

## Out of scope

- Slack rows and the 2 h Slack wait (016).
- The waiting banner, the composer and the quick starts (015).
- Starting a Claude session from a row (011, Q6).
- The sprint reads, the Tickets count and the board (008). ⌘K search across tools, messages and sessions (009); this list's own search box is in scope (Q9).
- Searching or filtering on the server, or keeping filters anywhere but the address.
- Writing to Jira or GitHub. Snoozing, dismissing or marking a row done.
- Desktop notifications or sounds.
- GitHub Enterprise, or more than one Jira site.
- Reading descriptions, comment text or check logs (015 and 013 send those to Claude).
- Showing Error in Settings › Connections when a sync is refused. The connection's state stays what connecting set.
