## Assumptions

Correct these now, or the work goes ahead on them.

- **This spec builds on 011, which isn't merged.** 011 is being built in another session (`feat/011-sessions-and-worktrees`, 9 of 33 tasks done on 18 Oct 2026). 012 needs its session store, the Claude adapter and its `canUseTool`, the tool decision (`agents/claude/tool-decision.ts`), the progress fold and its stepper rule, the Session screen, and the e2e fake Claude Code. This branch starts from `main` (PR #15) for the spec only. It moves onto `main` again once 011 merges, before /plan's first task. If 011 changes on its way (its review, or the real run in its Q13), these questions are checked again then.
- **What 012 takes over from 011.**
  - The adapter's `respond`.
  - The `Bash` tool, which 011 leaves out (011 Q6).
  - The Needs you state, `ActivityStep`'s `waiting` look and the stepper's Test step (011 AC-7, Q9b, Q9g).
  - The command side of agent-runtime rule 6: keeping Claude's commands away from Orynx's keychain items and `runtime.json`'s session token (011 Q8a).
  - The last two sentences of Claude's note, which 011 Q5 says change when commands arrive.
- **Claude gets one new tool: `Bash`.** Web tools, MCP tools, sub-agents and Claude's questions (`AskUserQuestion`) stay off, as in 011. Background commands (`run_in_background`) are refused, and Claude is told to run them in the foreground, so no command outlives its approval or its session. A command still runs for at most 10 minutes (Claude Code's own limit), and Stop ends it.
- **Every call Claude Code doesn't allow by itself reaches Orynx.** 011 passes `permissionMode: 'default'`, no settings sources and so no allow rules, so each `Bash`, `Edit` and `Write` call comes to `canUseTool`. With the sandbox (Q2), Orynx also passes `autoAllowBashIfSandboxed: false`, so a sandboxed command still comes to Orynx. If the pinned Claude Code lets some commands through by itself (read-only ones, say), the plan's probe will show it, and the work stops and asks.
- **Each call is decided with the settings as they are then.** Orynx reads the mode and the allow list through `createPreferencesService().read()` on every call. A change in Settings applies from Claude's next call, in every running session. A call already waiting keeps waiting until you answer it.
- **Waiting has no time limit.** A call waits until you answer it, press Stop or Discard, or Orynx closes. The SDK holds the call meanwhile. While any call waits the session is Needs you. Once none is left it's Working again.
- **Calls asked together wait in a queue.** Claude can ask for two commands in one message. The callout shows the oldest. When you answer it, the next one shows. The session stays Needs you until the queue is empty.
- **What each answer does.**
  - Allow once: this call runs. The same command asks again next time.
  - Always allow `<entry>` (Q1, Q4): Orynx adds the entry to the allow list, then runs this call. If the list can't be saved, nothing is decided, and the callout stays with an error (Q8e).
  - Deny: the call doesn't run. Claude is told "The user denied this. Don't try it another way. Carry on without it, or say in your summary what you needed." and carries on. Deny doesn't stop Claude. Stop does.
  - Stop or Discard while a call waits denies it, and the callout goes.
- **The first answer counts.** With the session open in two tabs, the first click decides. The other tab's callout goes with its next refresh, and a click that arrives late changes nothing.
- **A callout never takes focus, and no single key approves.** The callout announces itself (`role="alert"`) and leaves focus where it was, so a key pressed for something else can't approve anything (the SDK's own advice for hosts). After you answer, focus moves to the next callout's first button, or to the "Claude's progress" heading when none is left.
- **The allow list is one list for every repository.** It's saved in `settings.json` next to the mode (never a token), it starts empty, and it's used only in "Edit files and run allowed commands". Settings › Coding agent shows and edits it (Q6, as spec 005 said). Adding and removing send only the one change, like the inbox rules, so two quick changes can't undo each other.
- **Approvals are kept with the session.** The product spec lists approvals under a session's data. `session.json` records each call that asked: the command or the path, when it asked, the answer and who gave it (you, Stop, Discard, or Orynx closing). The terminal log names only the kind (command or edit) and the answer. It never holds the command text, the path, the change or the command's output, as in 011 AC-21.
- **A restart while a call waits** stops the session, as in 011 AC-14. The call is recorded as unanswered.
- **The stepper's Test step.** The stepper reaches Test with Claude's first command after its first edit. Commands before any edit (`git log`, a first test run) leave it on Plan. It never moves backwards (011 AC-7).
- **The API.** `POST /api/sessions/:id/approvals/:approvalId` takes `allow_once`, `always_allow` or `deny`. A late or repeated answer gets `409`, which the page treats as "already answered". `GET /api/sessions/:id` carries the waiting calls in order. The server sends kinds and values (the command, the path, the change, the reason it always asks, the entry Always allow would save). The app words them, as in 011. `PATCH /api/preferences` gains adding and removing one allow-list entry.
- **No new dependency.** Orynx reads a command with a small reader of its own (Q3). The sandbox is Claude Code's own (Q2). On Linux it needs `bubblewrap` and `socat` installed, which the install guide (018) will say.
- **Tests never run real commands against anything real.** Core tests fake the SDK at its boundary, as in 011, and test the decision as a table: every mode against every kind of command, as agent-runtime's testing section asks. The e2e fake Claude Code from 011 gains a scripted command that asks. The sandbox itself is checked in the user's real run (Q10), because a fake can't show what it blocks.

## Goal

When Claude wants to run a command, or to edit a file while I've asked to approve everything, it stops and asks me on the Session screen: Allow once, Always allow, or Deny. Commands I trust, such as `npm test`, can run without asking, and some commands always ask, whatever I picked. A command I let run can't reach my tokens, Orynx itself, or anything outside the worktree unless I allow that one command.

## Out of scope

- Claude's questions (`AskUserQuestion`), the follow-up box, and the Changes and Ticket tabs (013).
- Pushing and opening the pull request (014). Inside a session they're refused (Q7).
- Web tools, MCP tools, sub-agents and background commands.
- Showing a command's output in the progress. Claude's summary says what its checks found.
- An allow list per repository, and reading Claude Code's own allow rules from `~/.claude` or a repository's `.claude/settings.json`.
- Editing an entry in place. Remove it and add it again.
- Telling you outside the page: OS notifications, sounds, the tab's title, and Home's waiting banner (015).
- Answering from Home or the sidebar. You answer on the Session screen, and the Needs you rows lead there.
- A sandbox on Windows.
