## Assumptions

Correct these now, or the work goes ahead on them.

- **Three kinds of session, decided at Send, never changed after.** Orynx decides from the switch and the chips, not by asking Claude:

  | Kind                  | When                                                                                                                          | Where Claude works                                              | Steps                                       |
  | --------------------- | ----------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- | ------------------------------------------- |
  | **Ask**               | Ask is picked                                                                                                                 | Reads the folder in place, or no folder at all; changes nothing | None                                        |
  | **Build, new branch** | Build is picked, and the next row doesn't apply                                                                               | A new branch in its own worktree, as today                      | Plan · Build · Test · Review · Pull request |
  | **Build, your PR**    | Build is picked, no ticket chip, and the first PR chip is yours, open, not from a fork, and in the picked folder's repository | The PR's own branch in its own worktree; no new branch          | Plan · Build · Test · Review · Push         |

- **The Ask / Build switch comes back**, as spec 026 drew it before 19 Oct: a `SegmentedControl` labelled "Session" with "Ask" and "Build", each with its tooltip, in the composer's bar between + and the pickers. It remembers your last pick, as the model and effort do. The first time, it's Build.
- **Ask needs no folder.** In Ask, the folder picker gains "No folder" at its top and starts on it. Pick a folder and Claude reads its code in place (spec 026). With no folder, Claude reads only what you added: tickets, pull requests and files. Build still needs a folder, as today.
- **An Ask session with no folder** runs Claude in an empty folder of its own under Orynx's home, deleted with the session's other files. Claude still gets no edits and no commands (spec 026). The header and breadcrumb leave the folder out.
- **The home heading follows the switch**: "What should we ship today?" for Build, as now, and a new line for Ask (Q8b).
- **Ask has no stepper**, as spec 026 decided. Nothing in it waits for you, so a stepper would have nothing to show.
- **Test is "Skipped" when nothing was tested.** In a Build session, Test shows as skipped, not done, in two cases: Claude finishes while the stepper is still on Build (it ran no command after its first edit), or commands are off on this computer (spec 012, Q2b). A follow-up that runs a command later makes it done. This needs a new look in `Stepper` (Q5).
- **Build on your PR:**
  - Orynx fetches the PR's branch and makes the worktree from it with a detached HEAD. That way the branch can still be checked out in your main checkout. "Push changes" pushes the worktree's HEAD to the PR's branch, never with force, as spec 014 does.
  - The session is linked to the PR from the start. The page bar shows Open PR and Push changes, never Create pull request. The last step is **Push**, which the stepper reaches when you push. A follow-up after a push takes the stepper back to Build, as spec 014 does.
  - When someone else pushed to the branch since, Push changes says spec 014's line ("… already has fix/x with commits this worktree doesn't have. Orynx never overwrites them."). Merging their commits is out of scope.
  - Claude's brief already holds the PR's description, diff, failing checks and open review comments (spec 015). Claude's note tells it that it is on the PR's own branch and that Orynx pushes only on your click.
  - A PR that already has a live session on its branch answers `existing` and opens that session, as a ticket does (spec 011).
  - "Yours" means the PR's author is the GitHub login Orynx is connected as. Orynx reads the author, whether the PR is open and whether it comes from a fork in the GitHub query it already makes for the chip.
  - The picked folder's repository is the `owner/name` of its `origin` remote, which Orynx reads with git at Send.
- **Every other PR chip is context, as today**: someone else's PR, a closed or merged one, one from a fork, one in another repository, or any PR next to a ticket chip. Build then makes a new branch, and Ask reads the PR's description, diff and comments from the brief.
- **Home's rows need no new button.** "My pull requests with unresolved review comments" and "…with failing checks" already add the PR to the composer (spec 022). With Build picked, Send works on its branch.
- **No new dependency, token or colour.** The skipped look uses `border-control` and `text-muted-foreground`.

## Goal

When I only want an answer, I pick Ask and Claude answers without a folder, a branch or steps that don't apply. When I want work done, I pick Build. If the work is fixing my own pull request's review comments or failing checks, Claude works on that PR's branch and I push to it. The steps I see are only the ones the session really goes through.

## Out of scope

- Posting a review, or comments, to GitHub. Claude's suggestions stay in Orynx (Q4).
- Replying to or resolving review threads on GitHub after a push.
- Working on someone else's PR's branch, or a fork PR's branch.
- Merging or rebasing commits someone else pushed to the PR's branch.
- Letting Claude choose the kind, or changing a session's kind after Send, including "continue this Ask as a Build" (Q9).
- A third switch option such as "Review". Ask covers reviewing (Q4).
- Checking out a PR's own code for an Ask session (Q4).
