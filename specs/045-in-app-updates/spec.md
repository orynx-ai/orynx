# In-app updates: version, updates and what's new in Settings

Status: approved, every question answered (22 Oct 2026)
Roadmap: not on the roadmap. This is the user's ask from 22 Oct 2026: "can we have a in app update feature for both web and native apps?", then, once `orynx-ai/orynx` was public: "now the repo is public can we add a option in settings to show version and update thing also changelogs". The spec takes 045, the next free number after 044. The branch is `feat/045-in-app-updates`, made from `origin/main` at `5386483`.

## Assumptions

Correct these now, or the work goes ahead on them.

- **Three kinds of Orynx.** "Native" is the desktop app of spec 027 (`Orynx.app` on Apple Silicon, the AppImage on Linux). "Web" is the Orynx `./install.sh` runs from a clone as a service (the LaunchAgent `dev.orynx.server` on macOS, the systemd unit `orynx` on Linux), opened at `https://orynx.local`, at `http://127.0.0.1:4317` or as the phone's home-screen app (spec 040). The third is a clone you start by hand with `pnpm start` or `pnpm dev`: it gets the version and what's new, but no Update button, because nothing would start it again (Q3).
- **A new Settings tab, About**, last after Inbox rules, at `/settings/about` (Q1). It has three parts, top to bottom: Version, Updates and What's new.
- **The hub does the checking for every kind.** It asks GitHub's public REST API for `orynx-ai/orynx`'s last 10 releases (`GET https://api.github.com/repos/orynx-ai/orynx/releases?per_page=10`). It sends no token, cookie or account, and nothing about you. It asks when it starts, every 6 hours, and when you press Check for updates. It asks GitHub at most once a minute, because GitHub allows 60 calls an hour without a token. The answer is kept in memory and never saved. The call lives in its own integration client, like Jira's and GitHub's.
- **In the desktop app, Electron's updater keeps its job.** As in spec 027, it downloads updates and installs them (Linux, and the Mac if Q2 says so). The hub tells the page what the updater is doing through the `utilityProcess`'s `parentPort`. The page still talks only to the hub, and the window still gets no preload.
- **The version you see.** The desktop app shows its stamped version (`0.1.37`). A clone's `package.json` always says `0.1.0`, so a clone shows the release it was built from, read once at start with `git describe --tags --match 'v*'`. It shows `0.1.37` on the tag itself and `0.1.37 + 4 commits (abc1234)` after it. A clone with no release tag in its history shows only its commit (`abc1234`).
- **What counts as newer.** For the desktop app, the latest release's version is higher than its own. For a clone, the latest release's tag is higher than the newest release tag in the clone's history, or the clone has no release tag yet. Versions are compared as major.minor.patch numbers, with no new dependency.
- **What's new is each release's notes** from GitHub Releases, newest first, up to 10 (Q8). Each shows its version and date, with its notes drawn by `@devhub/ui`'s `Markdown`. Releases newer than yours are marked. A link goes to all releases on GitHub. Notes are text from GitHub: raw HTML shows as text and runs nothing, and links open in the browser (the default browser in the desktop app, through `links.ts`).
- **Updating never cuts off a session.** While any session is working or waiting for you, Update and Restart to update are disabled, and their reason says so. Orynx never updates or restarts without your click, except the Linux AppImage's install on quit (spec 027).
- **An installed clone knows it's a service.** `./install.sh` adds `DEVHUB_SERVICE=launchd` (or `systemd`) to the service it writes. `apps/server/src/config.ts` reads it, and `.env.example` lists it. Until you run `./install.sh` once more by hand, the clone counts as started by hand.
- **The update's log.** A clone's update writes everything `git` and `./install.sh` print to `<DEVHUB_HOME>/update.log`, replacing the last one. The About tab names that file when an update fails, so the reason is never only in a terminal.
- **Open pages learn about a new build from the Orynx restarted notice.** Every hub start makes a new session token (`apps/server/src/runtime-file.ts`), so after any restart a page left open gets a 401 and already shows "Orynx restarted · Reload the page to reconnect." (`StaleNotice` in `packages/app/src/shell/app-shell.tsx`). Reload loads the new version. `/api/status` gains no `build`, and the page that pressed Update reloads itself (AC-25). Changed while planning (Q6).
- **No release exists yet.** Every Release run so far failed (the macOS build) or was cancelled (Playwright ran out of time). Making Playwright not fail CI is on its own branch, `ci/e2e-not-required`, which the user asked for on 22 Oct 2026. Until a release is published, About says there are none (Q9).
- **No new dependency.** The page uses `@devhub/ui`'s `Tabs`, `SettingRow`, `Button`, `Pill`, `Markdown`, `CommandBlock`, `ExternalLink`, `EmptyState`, `Skeleton` and `Callout`. The hub uses `fetch` and `simple-git`.

## Goal

I can see which version of Orynx I'm running and what changed in each release, and I can update from inside Orynx: from the desktop app on my Mac or Linux, and from the Orynx I installed from a clone and use in the browser or on my phone. An update waits until no session is running, and when it fails I can see why.

## Out of scope

- Signing and notarizing the Mac app, Intel Macs and Windows.
- Updating without a click, other than the Linux AppImage's install on quit from spec 027.
- A beta channel, staged rollouts, picking a version, going back to an older one, and skipping a version.
- Updating Claude Code, `gh`, Node or your repositories.
- Updating a clone started by hand from the page (AC-30 only shows the commands).
- A Check for Updates item in the desktop app's menu.
- Fixing the Release workflow's failing macOS build. Making Playwright not fail CI is on `ci/e2e-not-required`.
- Telemetry: no one learns which version you run.
