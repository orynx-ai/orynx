# Session terminal

Status: approved
Roadmap: not on the roadmap. The user's ask, 20 Oct 2026: "I want to give support for terminal for a running [session]", with the mockup "12 · Terminal (full-screen dialog)". It takes 036, the next free number (035 is Sync activity). The branch is `feat/036-session-terminal` in `../dev-hub-036`, from `origin/main` at PR #41.

## Assumptions

Correct these now, or the work goes ahead on them.

- **"A running session" means a Build session whose worktree is still there**, whatever its state: working, needs you, done, PR open or stopped. An Ask session has no worktree, so it has no Terminal (Q9). Neither has a discarded session. Windows has none, as with Open ports (spec 032).
- **Where it opens**: a Terminal button in the Session screen's page bar, before Stop Claude, with `` ⌃` `` beside it, as drawn. Under 768 px it becomes an `IconButton` named "Terminal" with the shortcut in its tooltip. `` ⌃` `` opens and closes the dialog anywhere on the Session screen. Esc and Back to session close it, and focus returns to the Terminal button. It opens on the tab you last had open for this session; the first time, on your shell. A reload closes it.
- **The dialog fills the window**, 16 px in from each edge (8 px under 640 px), over a scrim, as drawn. Its header: the terminal icon, "Terminal", the session's title and ticket key (truncated, full text as a tooltip), "Claude needs you" while Claude waits and you're on another tab, and Back to session with `Esc`.
- **The Claude tab** is read-only. It lists every command Claude ran in this session, oldest first, across the first run and every follow-up. Each block shows the command, "Claude", its result (✓ and the time, ✗ failed and the time, ● running, ● waiting for you, or denied) and Copy. Its output sits under it. Claude's commands give no exit code, so a failed one says "failed" instead of a number. Orynx keeps the last 200 lines of each command's output, saved with the session. A session saved before this spec shows its commands with no output (Q8i).
- **A command waiting for your answer** shows in the Claude tab with the same reason line and the same choices as the session's approval callout (spec 012), not only the drawn Allow once and Deny (Q7). Answering in either place answers both.
- **Your shell tabs** run what you type in the session's worktree, as you, outside Claude's sandbox. Rule 11 doesn't apply to them: Claude never types here, and every command is your own Enter or click. Each command runs in your login shell (`$SHELL -l -c`), from the worktree's root, in a block of its own, as drawn (Q2). So:
  - `cd` and `export` don't carry over to the next command. Each one starts in the worktree.
  - Nothing reads from the keyboard. A command that asks a question gets no answer, and editors like `vim` don't work.
  - Output is plain text. Orynx asks tools not to colour it (`NO_COLOR=1`) and removes any colour codes left. Output and errors are shown together, in the order they came.
  - The block shows ✓ and the time, or ✗ exit _n_ and the time, as drawn.
  - Orynx's own settings and tokens are left out of the command's environment: every key in `.env.example`, and the session token.
- **One command at a time in a tab**, as in a real terminal. While one runs, its block shows Stop in place of Rerun, and `⌃C` in the input stops it too. Stop sends the command's process group SIGTERM, then SIGKILL after 5 seconds. To run something beside it, such as a server, open another tab with +.
- **Tabs**: the first shell tab is named after your shell ("zsh · worktree"), and + adds "zsh 2", "zsh 3"…, up to 5 shell tabs per session. An added tab has a close `IconButton` ("Close zsh 2"), which stops its command. The first one can't be closed. Tabs use arrow keys and a roving tab stop, as drawn.
- **Output kept**: the last 2,000 lines of each command, and the last 100 commands in each tab. Older ones drop off the top. Tabs, their output and what runs in them last while Orynx runs. When Orynx quits, a command still running ends. Discard changes stops every command in the session's tabs before it deletes the worktree. A server you start here is yours, as in spec 032 Q3: Claude finishing or Stop Claude never ends it.
- **↑ and ↓** in the input walk the commands you ran in this session, newest first, as drawn. Enter runs. Clear output (the bin icon), or typing `clear`, empties the tab.
- **Rerun** runs the block's command again as a new block at the bottom. **Copy** puts the command and its output on the clipboard, as `CopyButton` does.
- **Ask Claude to fix** shows on a failed block in your shell tab while the session can take a follow-up (spec 013). It sends Claude a follow-up with the command, its exit code and the output's last 50 lines (Q8f). It goes into the running Claude, or resumes it, as the follow-up box does. The dialog then moves to the Claude tab, which shows "Sent from your terminal: `<command>`". The output goes to Claude as it is, on your click only.
- **Output shows within half a second** of the command printing it, over the event stream Orynx already has. Nothing polls.
- **No new dependency**: commands run with `node:child_process`, and no terminal emulator is added (Q2).
- **Settled while building** (20 Oct 2026):
  - A command of Claude's still running when Claude's run ends (Stop, a problem, Orynx closing) shows "stopped".
  - The Claude tab's load error is "Couldn't load Claude's commands" with Try again. Your shell tab's is Q8e's "Couldn't reach Orynx."
  - "Close zsh 2" sits in the tab strip beside +, shown while an added tab is picked: a button inside a tab would be a button in a button.
  - - at five tabs is `aria-disabled` rather than disabled, so its tooltip can still say why.
  - The field takes focus on opening, after + and after Close, but not on arrowing between tabs, so the tab strip keeps the arrow keys.
  - Typing `clear` empties the tab rather than running a command.
  - Ask Claude to fix that can't go says why in the follow-up box's words.
  - Each block is a group named by its command.
- **Left out of the drawing** (Q3, Q4): the npm run dev tab with Open localhost, Restart and Stop; the Quick run chips with Edit list; and Search output.

## Goal

While Claude works on a ticket, I can open a terminal on its worktree without leaving Orynx. I can see every command Claude ran with its output, answer it when it waits, and run my own commands, like the tests or `git status`, in the same worktree. When one of mine fails, I hand it to Claude in one click.

## Out of scope

- A real terminal: interactive programs, colours, `cd` that carries over, or typing into a running command (Q2).
- The dev-server tab with Open localhost, Restart and Stop (Q3). Open ports (spec 032) shows what listens.
- Quick run chips and their list in Settings (Q4).
- Search output. The browser's own find works in the web app. In the desktop app it waits for a later spec.
- Typing into the Claude tab, rerunning Claude's commands, or moving a command from one tab to another.
- Keeping your shell tabs, or their output, after Orynx quits.
- A terminal for Ask sessions, discarded sessions, or on Windows.
- A side panel or split view instead of the full-screen dialog.
