# New ticket in Jira: the column + and New ticket make a Jira issue in that column, in the sprint you're looking at

Status: approved
Roadmap: Phase 2 — Inbox and tickets, spec 019 (`019-new-ticket`). Spec 008 moved the column + and the form here (008 Q5), and spec 037 left Jira's New ticket to it (037 Q1). The user asked on 2 Nov 2026 to build it with spec 046 "in one session and one pull request", so it shares the branch `feat/046-019-trace-steps-and-jira-ticket`, made from `origin/main` at `edc8ad7`.

## Assumptions

Correct these now, or the work goes ahead on them.

- **One dialog, two places to save.** Spec 037's New ticket dialog gains a choice at its top: Jira (the project Tickets shows) or Orynx. Everything else about Orynx's tickets stays as it is. There's no second dialog and no second button.
- **The project is the one Tickets shows.** That's the page bar's Project. With no project picked ("Your sprint"), it's the project of the sprint on screen. With no project and No sprint, or with Jira not connected, or with only Orynx ticked in Source, Jira isn't offered and the dialog is spec 037's, unchanged. The dialog never asks for a project.
- **The sprint is the one Tickets shows.** A new Jira issue goes into the sprint on screen, active or future. With No sprint picked it goes into no sprint, the backlog.
- **The column is the status.** The column's + starts the issue in that column. Jira always makes an issue in its workflow's first status, so Orynx then moves it by one of the issue's own transitions to a status the board puts in that column, matched by status id within the issue's workflow (never by name across workflows, as spec 044 does). For To do, that's usually no move at all. The page bar's New starts in To do, as it does today.
- **What Orynx sends Jira:** the title as Summary, the description as Jira's own format (the same Markdown converter comments use, spec 044), the type, the priority, the due date when the type's create screen has one, and you as Assignee (Q4). Labels, components, epics, story points and anything else are left at Jira's defaults.
- **Jira's limits are the form's limits.** Title 255 characters and description 32,000, as 037's form already checks.
- **After Create ticket**, the dialog closes and Tickets reads the sprint again at once, as Sync does, so the new card shows in its column without waiting for the 2-minute refresh. Focus goes back to the button that opened the dialog, as in spec 037.
- **Jira's answers are never cached or logged.** The project's types and priorities are read each time the dialog opens on Jira, as `issue()` is.
- **One request makes one issue.** A double press, Enter held down or a retry after a timeout never makes two. Once Jira has made the issue, Orynx never makes it again and never deletes it.
- **Source set to Jira only** (the user's call, 2 Nov 2026): New and each column's + still show, and make Jira tickets. Save in offers Orynx only while Orynx's tickets show, so a new ticket never lands out of view (spec 037's rule).
- **When the workflow has no move into the column** (the user's call, 2 Nov 2026): "Made MAI-142, but Jira didn't move it to In review: its workflow has no move there from To Do."
- **No new dependency.** Jira's create, create-metadata, sprint and transition endpoints go through the existing `jira/client.ts`. The dialog uses `@devhub/ui`'s `SegmentedControl`, `Select`, `Skeleton` and 037's `TicketForm`.

## Goal

When I press + on a column of my Jira sprint, I can make the Jira ticket right there: title, description, type and priority. It lands in that column and that sprint, assigned to me, and shows on the board straight away. If Jira won't take it, I see Jira's own reason and keep what I typed.

## Out of scope

- Editing or deleting a Jira issue from Orynx. The ticket dialog keeps Open in Jira.
- Fields beyond title, description, type, priority, status, due date and you as assignee: labels, components, epic, parent, story points, sub-tasks, an assignee picker, attachments.
- Picking a project or sprint inside the dialog. It uses what Tickets shows.
- New Jira tickets from Home, the composer, the ⌘K search or Claude's Jira tools.
- Showing Jira's extra required fields so you can fill them in (Q3).
- Remembering the last Save in choice, unless Q1 picks (c).
- Undoing a new Jira issue.
