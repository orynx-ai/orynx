## Assumptions

Correct these now, or the work goes ahead on them.

- **Tickets' toolbar shows two filters, then a Filters button.** Source and Assignee stay as they are today, as `FilterMenu`s. After them comes a `Filters` button with the filter icon. When any filter in the sheet differs from its default, the button shows how many differ, as `FilterMenu` shows its ticked count. "Clear filters" and the live ticket count stay at the toolbar's far end. The toolbar's leading filter icon goes, because the button now carries it.
- **The filter sheet slides in from the right.** It is a new `@devhub/ui` component, `Sheet`, built on the same Radix Dialog as `Dialog`, with a story for each state and a test. Focus moves into it and stays there. Esc, the close button or a click outside closes it, and focus goes back to Filters. It is 400 px wide, and full width under 480 px. It is titled "Filters" and holds, top to bottom: Project, Sprint, Source, Assignee, Status, Type, Priority and Due. Project and Sprint are the existing pickers. Every other filter is a list of checkboxes inside a `fieldset` with a legend. Assignee gets a search field above its list once it has more than 8 people. Each tick applies at once, so the board behind the sheet changes as you tick and nothing waits for an Apply button. The sheet's foot holds the live count ("11 tickets") and "Clear filters".
- **Project and Sprint are also in the page bar.** The breadcrumb becomes "Tickets / [Project ▾] / [Sprint ▾]", for example "Tickets / MAI ▾ / No sprint ▾". Each crumb is the same picker as in the sheet, drawn as a plain `Picker`, so the project no longer sits as grey meta text beside the sprint. The sprint's dates ("ends in 3 days") stay as page bar meta. With Orynx's tickets alone, both pickers hide and the breadcrumb reads "Tickets / Orynx", as it does today. Under 768 px the sprint crumb is cut short with an ellipsis, so the bar keeps to one line.
- **Tickets remembers its filters on this computer.** The six address filters are written to the Tickets store, which `devhub.tickets` already keeps in local storage. When you open Tickets with no filters in the address (from the sidebar, for example), the remembered ones come back before the first paint, so nothing jumps. An address that names filters, such as a link from Home, still wins and becomes the remembered set. Clear filters goes back to the default (Assignee: Me) and remembers that. The search text is not remembered: it is for one visit, as spec 008 Q3e decided. Project and Sprint are already remembered by the server (spec 020).
- **"Refresh" becomes "Sync".** The button on Home and Tickets keeps its arrow icon and what it does: one sync of Jira and GitHub now. Only its word changes. While it runs, it reads "Syncing" and its arrow turns.
- **"Synced just now" becomes the Sync activity button (Q2).** The separate "Sync activity" button goes. The quiet line that says when the tools last synced becomes a ghost button that opens the Sync activity dialog, with the status dot before its words: green while syncs go well, red when a tool needs attention, as spec 035 drew it. Its accessible name starts with its visible words, so voice control can reach it: "Synced just now, Sync activity", or "Synced just now, Sync activity, 2 tools need attention". Tickets' page bar gets the same button, so both pages read "[● Synced just now] [⟳ Sync]". Under 768 px, where the line used to hide, the button shows only its dot and the history icon, with "Sync activity" in its tooltip.
- **The Sessions page gets a search field and two filters, like Claude's own list.**
  - Search sessions: the title, the ticket key or the pull request in any case, as you type.
  - Status: Working, Needs you, Done, PR open and Stopped, as the state icons name them.
  - Kind: Ask and Build.
  - The search text and filters live in the address (`/sessions?q=…&status=done`), so a reload keeps them.
  - With nothing matching, the page shows "No sessions match" with a Clear filters button.
  - The page reads every session at once, as it does today, and filters in the browser. This is a `shortcut:` comment: move the search to the server once a person keeps thousands of sessions.
- **Recent searches, in three places (Q3).** The Sessions search, ⌘K search and Tickets' search each remember their own last 5 searches on this computer, newest first, each search once. A search counts once you press Enter in the field, or once you open a result from it. When the field has focus and is empty, a "Recent searches" list shows under it: under the field on Sessions and Tickets, and in place of ⌘K's hint line in ⌘K. Picking a search runs it again. Each row has a remove button, and "Clear" empties that place's list. Arrow keys move through the list, as `SuggestionList` already does. A search never leaves the computer. Tickets' search text is still not kept in the address (spec 008 Q3e); only its recent list is remembered.
- **Sessions can be pinned.** A pinned session moves to a "Pinned" group at the top of the sidebar's Sessions section and of the Sessions page, in the order you pinned them. The pin is kept on the server, in the session's own file (a new `pinnedAt` field, null by default), so the desktop app and the browser agree. Pinning never changes the session's activity time or its place among the unpinned.
- **Sessions can be renamed.** Rename opens a small dialog with one field, "Name", filled with the current title and selected. It takes 1 to 200 characters; spaces at either end are trimmed, and a name of only spaces is refused. It uses react-hook-form with the contract's zod schema. The new title shows everywhere the old one did: the sidebar, the Sessions page, the page bar, ⌘K and notifications. Claude's own work is not changed.
- **Sessions can be deleted (see Q1).** Delete asks first, in an `AlertDialog`: "Delete this session?" When the worktree holds changes that haven't been pushed, it adds "Its changes that haven't been pushed will be lost." Delete removes the session's file, its brief and its worktree folder. The git branch stays in your repository, so committed work can still be found. While Claude is working, Delete is offered but disabled, with the reason "Stop the session first". After a delete from the Session screen, Orynx goes to the Sessions page. There is no "Session deleted" toast: Orynx has no toast for its own messages (only notifications' pop-ups), so the row going away and focus moving on say it (found while building, 20 Oct 2026).
- **The ⋯ menu.** On the sidebar and the Sessions page, a ⋯ icon button ("More actions for <title>") appears at the row's right end when the pointer is over the row or anything in it has keyboard focus. Under 768 px it always shows, because a phone has no hover. It is a sibling of the row's link, never inside it, so the row has two separate controls. The menu holds Rename, Pin or Unpin, then a separator, then Delete in the danger colour. On the Session screen the same three items join the page bar's existing More actions menu (spec 038), above Discard changes.
- **The sidebar gets smaller type and icons (Q4).** The width and the two-line session rows stay as they are. Inside the sidebar, the text and icons go one step down the scale. Place names, the Search button and session titles go from `body` (16 px) to `small` (14 px), keeping weight 500. Session rows' second lines and the Sessions heading go from `small` (14 px) to `label` (12 px). Icons go from 20 px to 16 px, and the session state circles from 24 px to 20 px. Places and Search go from 40 px to 36 px tall, still above the 32 px hit-target minimum, and session rows shrink with their type, from about 56 px to 48 px. Counts stay at `label`. Nothing outside the sidebar changes. `docs/design/design-system.md`'s SidebarNav section is updated to say so (Q6).
- **The New ticket dialog says where the ticket goes.** Under the heading, one quiet line with the Orynx mark reads: "Saved in Orynx on this computer. It isn't added to Jira." Without Jira connected, it reads "Saved in Orynx on this computer." The column + and New ticket open the same dialog, so both show the line.
- **No new dependency.** `Sheet` uses `radix-ui`'s Dialog, which `@devhub/ui` already has. Every icon comes from `@hugeicons/core-free-icons`.

These replace the assumptions above where they differ.

- **The filter sheet is a list of rows, then a page per filter** (the user's screenshots of a people directory's filters). ## Goal

Tickets shows the two filters you use all the time and keeps the rest one click away in a sheet. It keeps your filters when you leave and come back, and you can switch project and sprint from the page bar. Sessions become something you can find, keep and tidy up: search them and filter them, with recent searches, and rename, pin or delete them from the sidebar, the Sessions page or the session itself. The sidebar takes less room, Sync says what it does, and a new ticket says it lives in Orynx.

## Out of scope

- Moving filters out of Home's attention list. Home keeps its tabs.
- Server-side search or paging on the Sessions page (see the `shortcut:` in the Assumptions).
- Bulk rename, bulk pin or bulk delete.
- Archiving, which would be a fourth state between kept and deleted.
- A narrower sidebar or one-line session rows (Q4 kept both as they are).
- Renaming Claude Code's own session, or the git branch.
- Deleting the git branch when a session is deleted.
- Saved filter sets ("views") with names.
