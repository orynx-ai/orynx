# Plan: Design-system components

Spec: `specs/006-design-system-components/spec.md`

## Order of work

Everything is in `packages/ui`. Nothing in contracts, core, api-client or app changes, so the order goes from the smallest parts to the parts built from them. Each part can be tested on its own.

Where shadcn or its AI Elements patterns have the part (spec Q6), the task starts from that code: copied by hand from the registry (`https://ui.shadcn.com/r/styles/new-york-v4/<item>.json`, or `radix-vega` for `code-block` and `trace`, which only the newer styles have), then restyled to tokens with the add-ui-component table. Running `shadcn add` would overwrite our `Button` and `Input` and pull in Shiki.

1. **`Skeleton` first** (Q4a), from shadcn's `skeleton` without its pulse. It's one block, and the loading forms of the card, row, file list and diff are built from it later.
2. **The small stand-alone parts:** SegmentedControl (from `toggle-group`), Stepper, StatusIcon, ActivityStep (from `trace`, as AI Elements' Task pattern uses it), Chip (the filter toggle, and the quick start from the Suggestion pattern) and Panel. Each is one file with no new behaviour beyond a pressed state or a link, so they're quick and cover AC-1 to AC-3 and AC-25.
3. **Menu**, from shadcn's `dropdown-menu` (Radix underneath, already installed), together with `Picker`, the 32 px button that opens it. The Composer's + button and pickers need both, so they come before the Composer. The first Menu test also shows which browser APIs jsdom lacks for Radix (see Risks).
4. **Composer**, from AI Elements' Prompt Input pattern (`input-group` for the box and bar, `attachment` for the context chips), in four steps: the Home ("task") look and its keys; sending states and growing; context chips with remove and focus; the Session ("follow-up") look. The Composer passes its text box's props through so react-hook-form's `register` works. `@devhub/ui` can't import react-hook-form, so the test drives the Composer with a plain form.
5. **AgentChip, then WorkItemCard.** The chip uses `sessionStateLabels` and `SessionItem`'s colours (Q3d) and stands alone in the list view too, so it's its own part. The card has several links, so its title and its action are their own parts that each take `asChild`; a router `Link` can go in each.
6. **AttentionRow** with its `<ul>` list, and its narrow layout as a container query (Q4b), so it works in any panel width rather than only in a narrow window.
7. **FileList, then DiffView.** FileList stays the design system's flat list (Q6c). DiffView starts from `code-block`, whose lines already have `added` and `removed` variants, without its Shiki highlighter (Q6b). Both take ready-made data (paths and counts; lines with a kind and numbers). DiffView's hunk rows and loading form are a second step.
8. **ResumeBanner.**
9. **Design map and browser check.** Mark every part built in `docs/design-map.md` in one commit, which keeps the table in step and limits the overlap with 005. Then open every story in a real browser at 360 and 1280 px, in light and dark, with axe, and fix what turns up.
10. **`/review`.**

Each part gets its export in `packages/ui/src/index.ts`, a story for each state, and a test (behaviour and `expectNoAxeViolations`) in the same commit. The stories use the screens' words.

## Risks

| Risk                                                                                                                                                                                   | How we will notice early                                                                              | What we do                                                                                                                                                                                  |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Radix's menu needs browser APIs jsdom doesn't have (`ResizeObserver`, pointer capture, `scrollIntoView`)                                                                               | The first Menu test (task 8) throws a `ReferenceError` or never opens                                 | Add the smallest stand-ins for those browser APIs to `packages/ui/src/test/setup.ts`. That fakes the browser, not our code, so honest-tests allows it                                       |
| jsdom does no layout, so the ellipses, the two-line title, the 480 px wrap, the diff's sideways scroll, the 32 px hit areas and "nothing moves" when loading can't be proven in Vitest | Known in advance (honest-tests, "jsdom limits")                                                       | Vitest proves roles, names, keys and state. Task 23 opens every story in a real browser at 360 and 1280 px, in both themes, measures sizes and runs axe                                     |
| Radix renders the menu in a portal outside the story's frame, so it might miss the theme or the fonts                                                                                  | The Menu story in dark looks light, or the font changes                                               | Tokens live on `:root` and `data-theme` is on `<html>`, so a portal should inherit both. Check it in task 23                                                                                |
| Radix's menu markup or keys differ from the design system (focus on open, wrap-around, typeahead)                                                                                      | The AC-4 and AC-5 tests fail                                                                          | Use Radix's props (`loop`, `onCloseAutoFocus`) rather than our own key handling                                                                                                             |
| The text box doesn't grow in browsers without CSS `field-sizing`                                                                                                                       | Task 11's story doesn't grow in Firefox or Safari                                                     | Resize from `scrollHeight` on input, capped at 8 lines, rather than rely on `field-sizing` alone                                                                                            |
| Enter while an input method is composing would send half a word                                                                                                                        | The AC-9 test sends a keydown with `isComposing` and checks nothing is sent                           | Ignore Enter while `isComposing` is true (or `keyCode` is 229)                                                                                                                              |
| A component with several links can't use one `asChild`                                                                                                                                 | Typing the WorkItemCard props in task 15                                                              | Each link is its own small part (card title, card action, AgentChip, row title, row action) with its own `asChild`                                                                          |
| 005 merges first and touches the same files                                                                                                                                            | `git rebase origin/main` after 005 merges stops on `packages/ui/src/index.ts` or `docs/design-map.md` | Keep both sides: 005's Select, Checkbox and SourceMark rows, then ours. AttentionRow passes `label="hidden"` to `SourceMark`, which 005's version keeps, so typecheck should pass unchanged |
| Registry code uses classes this theme leaves out (`text-sm`, `dark:`, `destructive`, `ring-3`, `bg-accent`, `shadow-xs`) and shadcn's `IconPlaceholder`                                | `pnpm gate style-policy` (also a hook while editing) and `pnpm typecheck` fail on the copied file     | Restyle with the add-ui-component table and the `dh-*` CSS before the first commit; use lucide icons in place of `IconPlaceholder`                                                          |
| The registry's markup misses something the spec asks for (a hidden label, `aria-current`, a list instead of divs, Enter while composing)                                               | The part's AC test fails                                                                              | The spec wins: change the copied code. It's ours once copied                                                                                                                                |
| Coverage drops under 90% because some branches only run in a real browser                                                                                                              | `pnpm test:coverage` in task 23                                                                       | Test every prop branch in Vitest (tones, states, optional parts). Never add a test only to raise the number                                                                                 |

## Touches

- Packages: `ui` only. Docs: `docs/design-map.md` (the Components table). Spec files.
- Gates that check this work: `style-policy` (tokens only; also a hook while editing), `component-coverage` (a story and a test for each part), `boundaries` (`ui` imports no other `@devhub/*`), `test-policy` (no `vi.mock` of our code, no `data-testid`), `specs`, then `pnpm typecheck`, `pnpm lint`, `pnpm test` with 90% coverage.
- Skills to follow: `.claude/skills/add-ui-component/SKILL.md`, `.claude/skills/clean-ui/SKILL.md`, `.claude/skills/honest-tests/SKILL.md`, `.claude/skills/forms/SKILL.md` (so the Composer works with `register`).
