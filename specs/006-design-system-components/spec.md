# Design-system components

Status: approved
Roadmap: Phase 2 — Inbox and tickets (the design system in React)

## Assumptions

Correct these now, or the work goes ahead on them.

- **Build order.** Spec 005 is still being built on its own branch. This branch starts from `main` as it is today (6285e24), so it doesn't yet have 005's `Select`, `Checkbox` or the logo `SourceMark`. When 005 merges, this branch moves onto it. The only overlap expected is `packages/ui/src/index.ts` and the Components table in `docs/design-map.md`. AttentionRow uses `SourceMark`, so it gets 005's logos without extra work.
- **Choice card is already built** (spec 004 Q4), so it isn't built again. The roadmap row still lists it.
- **Parts only, no screen.** Nothing changes in `packages/app`, the server, contracts or the API. The new parts live in Storybook until 007 (Home inbox), 008 (Tickets), 011 and 013 (Session) and 015 (Home composer) use them.
- **Plain props.** `@devhub/ui` imports no other `@devhub/*` package, so each part takes strings, numbers, links and callbacks, never a contract type. Each screen turns its own data into props. Every visible word is a prop, so the screen specs decide the final wording. The stories use the design's words. The few words a part owns itself are in Q5.
- **Links stay links.** Anything that goes somewhere (a card title, an agent chip, a row's title and action, the resume banner, a menu's link item) is a real link and takes the router's `Link` through `asChild`, like `Button`.
- **No new dependency.** Menu is built on the Radix dropdown menu that the installed `radix-ui` package already includes. Nothing parses diffs or colours code. DiffView takes lines that are already split, and 013 turns git's output into them.
- **The Composer works with react-hook-form.** `@devhub/ui` can't import it, so the Composer passes its text box's props through (so `register` works), and Enter sends the form the normal way. The screen keeps the schema and validation (rule 12).
- **Markup that would fail axe is fixed, not copied.** The design system puts `role="list"` on a `div` of buttons (FileList), and the Session screen puts `role="listitem"` on a button. Lists become real `<ul>` and `<li>` with buttons inside, so they pass axe and stay buttons. The same goes for AttentionRow and the context chips.
- **Sizes come from design system 1.1, not from the screens.** The screens were drawn at 1.0 sizes, and the design system says to read sizes through it. The sizes it calls provisional are confirmed in Q2.
- **The segmented control is a row of toggle buttons**, as the design system marks it (`role="group"`, `aria-pressed`). Tab reaches each one, and Space or Enter presses it. It isn't a tab list.
- **No motion.** Menus appear and disappear without animation, because the product spec says no motion is needed.
- **Copying from a diff copies only the code.** Line numbers and signs can't be selected.

## Goal

Before Home, Tickets and Session are built, I want every part they need to be in `@devhub/ui`, drawn the way the design system draws them, usable by keyboard and screen reader, in light and dark. Then the screen specs only put parts together and never style one ad hoc.

## Out of scope

- Using any of these parts on a screen (007, 008, 011, 013, 015).
- The + Add context searchable list, turning a pasted key into a chip, and what Send does (015), unless Q1c brings the list into this spec.
- Parsing git's diff output, coloured code, side-by-side diffs, word-level changes, binary or renamed files, and updating the diff live (013).
- Board columns, the list-view table, and the search field with its icon (008 and 009).
- When a ticket counts as due soon or overdue, how wait times read ("2 d", "3 h"), and their wording (007 and 008).
- Stepper states other than done, current and to do, such as stopped or failed (011).
- Changing `tokens.css` or `docs/design/design-system.md`. Once Q2 is answered, a person updates the design system's "Provisional" note.
- Dragging cards between columns (not in version 1).
