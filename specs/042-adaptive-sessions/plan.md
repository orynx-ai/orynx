# Plan: Adaptive sessions

Spec: `specs/042-adaptive-sessions/spec.md`

## Order of work

1. **Contracts first** (rule 2). `Session.steps` (`{ kind, label, state }`), `intent`, `branchFrom`, a nullable `branch` on the worktree activity, the new activities (`reading`, `steps_changed`, `branch_made`, `server`), the `server` approval, the quick read's answer schema and the ports bodies. Stored sessions keep parsing: `file-session-store.ts` turns an old `step` + `skipped` into today's five steps. Everything after this builds on these types.
2. **Steps, pure** (`packages/core/src/sessions/steps.ts`, beside `progress.ts`). The strict rules (1–5 steps, 16-character labels, the last-step rule, who may mark which kind) and the moves by kind, as a table-tested pure module. `progress.ts` stops owning `stepOrder` and calls it. Tested alone, before anything calls it.
3. **The quick read** (`ask-reading.ts`: the prompt, the parse, the checks) and **branch rules** (`branch-rules.ts`: reading the repository's written rules and your recent branches, read-only). `AgentAdapter.write()` gains `model` and `effort`. Pure parts tested as tables; git parts against a temp repository, as `worktrees.test.ts` does.
4. **The session runs on it.** `session-service.ts` `run()` makes the reading row, calls the quick read, then prepares the worktree detached at the base. The branch is made by a new `worktrees.makeBranch()` when the first edit is allowed (a `beforeEdit` hook in `AgentRunOptions`, which the adapter awaits in `canUseTool`) or at Create pull request. A named branch on `origin` takes spec 031's detached path.
5. **Claude's new `orynx` tools**: `set_steps`, `start_server`, `stop_server`, defined once (as spec 037's ticket tools are) and offered by the Claude adapter. `start_server` asks through the approval callout and runs in a Terminal tab via `terminal-service.ts`, which learns to start a tab with a command and to report its shell's PID.
6. **Ports**: `packages/core/src/ports/` reads `lsof`, finds the session's listeners (child of its tabs or Claude's commands, or cwd inside the worktree), probes https/http once per new port, stops (re-checked) and restarts. Routes, then `@devhub/api-client`.
7. **UI**: `Stepper` shows only the current label below 640 px; a new `PortRow` in `@devhub/ui`. Then the app: step words, the stepper from `steps`, the header ("No branch yet", the address link), the Ports panel and tab order, the server approval, the Delete dialog's line.
8. **e2e last**: the fake Claude answers the quick read (default change steps unless the title asks otherwise, so older e2e files stay as they are), plays `set_steps` and `start_server`; one new e2e file walks AC-1 to AC-4.
