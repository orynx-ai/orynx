# Home composer and context

Status: approved
Roadmap: Phase 3 — Claude sessions

## Assumptions

Correct these now, or the work goes ahead on them.

- **015 doesn't need 014's code.** The branch `feat/015-home-composer-and-context` starts from `main` at PR #22 (020), in `../dev-hub-015`, while 014 is being built in another session. Everything 015 uses is on `main`: the session with its worktree, brief and Session screen (011, 012, 013), Ship's start flow and Settings' folder dialog (020), the search index (009), the inbox (007), and the parts 006 built (Composer, ContextChip, Picker, Menu, Chip, ResumeBanner). A session's `source` is already nullable, and `brief.ts` already puts a message before the chips.
- **One part waits for 014.** 014 leaves "sessions without a ticket" to 015 (014, Out of scope). So the pull request of a session with no ticket (its title, its description's Jira line, the draft's fallback) is 015's last task, and it starts only once 014 has merged. The branch moves onto `main` with 014 merged before that task.
- **014 and 015 change the same files.** Both change `packages/contracts/src/session.ts`, `packages/core/src/sessions/session-service.ts` and the Session screen. 014 adds methods and fields, and 015 changes how a session starts and what it shows without a ticket. Expect conflicts when this branch moves onto `main`, not a design clash.
- **What Send does.** It asks the server to start a session with your message, the folder and the chips. The server reads every chip first (the ticket from Jira, the pull request from GitHub), builds the brief, and only then makes the branch and worktree and starts Claude, as 011 does. If a read fails, nothing is made, and the composer keeps your draft and says what failed. On success Orynx opens the session.
- **The brief is exactly what you see** (agent-runtime rule 5). It is your message, then each chip in the order you added it. Nothing else is added: no other ticket, no Slack, no file you didn't pick. It's saved as `brief.md` (0600), as 011 saves it. Logs and events never carry the message, a file's text, a description, a comment or a diff line, only ids, keys and counts.
- **Limits.** The message holds at most 10,000 characters, as a follow-up does (013). A session takes at most 1 Jira ticket (Q2), 3 pull requests and 5 files, each file at most 100 KB of text (Q5). A pull request's diff goes up to its first 2,000 lines, then counts only, as 013 Q5 and 014 Q4 cut it.
- **The rules from 011 still hold.** At most three sessions work at once. A ticket has at most one live session (Q9). A session works in one folder, on a new branch from the folder's base, in a worktree under `~/.devhub/worktrees/`. A pull request chip is context only: Claude still works on a new branch, never on that pull request's branch (that is the "Fix" spec, 011 Q12).
- **The context lists read what Orynx already holds.** The Jira and Pull request lists filter 009's search index in the browser: tickets assigned to you or in the current sprint, and your open pull requests or ones waiting for your review. Typing an exact key (`PROJ-9999`) or pasting a pull request link adds one that isn't in the list. Orynx checks it with Jira or GitHub only at Send. The Git repository list is Settings › Repositories.
- **New reads, no new writes.** Jira: one issue's comments and linked issues (`GET /rest/api/3/issue/{key}` with `comment` and `issuelinks`), through the Jira client. GitHub: one pull request's description, diff, failing checks and unresolved review comments, through the GitHub client with your token. Neither writes anything. Tests fake both with MSW, and the e2e hubs' fakes learn them.
- **No new dependency.** Files are read in the browser with the standard `File` API. Nothing parses PDFs or images (Q5).
- **The draft lives in the page.** What you've typed, the chips and the folder you picked stay in a zustand store while Orynx is open, so leaving Home and coming back keeps them (Q14). A reload or a successful Send clears them. Nothing goes to disk except the folder you last used, as a preference.
- **New task (⌘N) focuses the composer**, as spec 001 said it would once 015 shipped.
- **`docs/product/spec.md` isn't edited here.** If the answers change what it says (Slack thread, the quick starts), the branch leaves the user a script for those edits, as 020 did.

## Goal

From Home I can tell Claude what to build in my own words, point it at a folder, and add a ticket, a pull request or a file it should read, without going through Tickets first. I see exactly what Claude will get before I press Send. And when a session is waiting on me, Home says so at the top.

## Out of scope

- Slack threads as context, and the "Draft a Slack reply" quick start (016).
- "Fix failing checks": a session on a pull request's own branch with its check logs (011 Q12's Fix spec). A pull request chip here gives Claude the PR as text only.
- PDFs, images and other binary files as context (Q5).
- Adding context to a follow-up. Follow-ups stay text only (013).
- Agents other than Claude (010).
- Saving drafts across a reload, or several drafts.
- New Jira or GitHub searches. The lists filter what Orynx already holds (009).
- Editing `docs/product/spec.md`.
