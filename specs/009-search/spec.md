# Search

Status: approved
Roadmap: Phase 2 — Inbox and tickets

## Assumptions

Correct these now, or the work goes ahead on them.

- **Build order, and what this waits on.** On 2026-10-18 the user asked to start 009 while another session finishes 008. This branch starts from `main` at the PR #10 merge, which holds 005, 006 and 007. Search finds the sprint's tickets, which only 008 reads, so the tasks that read them come last and start after 008 merges (Q1d). The dialog, ⌘K, assigned issues, pull requests and sessions need nothing from 008. When 008 merges, its own `SearchField` will clash with the one on `main`; this branch takes 008's.
- **Search finds what DevHub already holds** (Q1a). It reads DevHub's cache and session store, never Jira or GitHub, so it answers at once and works offline:
  - **Tickets:** the issues assigned to you that aren't Done (007's sync, up to 100), and every ticket in the current sprint (008's sync, up to 300). A ticket in both shows once.
  - **Pull requests:** the open pull requests that wait for your review, and your own open pull requests (007's sync, up to 100 of each). Today the cache keeps only the ones an inbox rule matches. Search needs all of them (Q1c).
  - **Sessions:** every Claude session in the session store, newest first. Nothing creates a session until 011, so this group stays empty until then.
  - **Messages:** none until Slack arrives in 016 (Q1b).
- **Inbox rules don't hide anything from search.** Turning off "Pull requests waiting for my review" takes those rows off Home, but search still finds them.
- **One list from the server, matched in the browser.** A new endpoint, `GET /api/search`, returns every searchable item: titles and metadata only, about 700 rows at most. Its zod schema lives in `@devhub/contracts`. The browser asks for the list when the dialog first opens. The events that already exist keep it fresh: `inbox.changed`, 008's tickets event and `sessions.changed`. Typing never sends a request.
- **Matching is Home's rule** (007 Q10a). Every word you type must appear in the item's text, ignoring case. It isn't fuzzy, so "archve" finds nothing. Each kind is matched on:
  - Tickets: key, title and status.
  - Pull requests: title, repository, number ("2841" or "#2841") and author.
  - Sessions: title, the ticket key or pull request number, and the state word.
- **Order** (Q2a). Groups come in a fixed order: Tickets, Pull requests, Sessions, with Messages after 016. Inside a group, an exact key or number comes first ("PROJ-1423", "2841", "#2841"). The rest keep the group's own order:
  - Tickets: the sprint in Jira's rank order, then the other assigned issues by key.
  - Pull requests and sessions: newest first.
- **At most 6 per group** (Q2b). When more match, the group's label says how many ("Tickets · 6 of 23"), and typing more narrows the group.
- **Opening a result** closes the dialog and goes where Home and Tickets go (Q2c):
  - A ticket with a session opens the session in DevHub. Any other ticket opens in Jira in a new tab.
  - A pull request opens on GitHub in a new tab, on its main page.
  - A session opens in DevHub.
- **Session states use the sidebar's words and icons,** from `SessionItem`: "Needs you", "Working", "Done, ready for PR", "PR open" and "Stopped".
- **The dialog opens empty every time.** The text you typed is dropped when it closes, and it never goes in the address.
- **The key is ⌘K on a Mac and Ctrl+K elsewhere,** as the Search button already shows. It works from anywhere in DevHub, even while you type in a field. Pressing it while the dialog is open closes it (Q2d). Browsers let a page take this key, as GitHub and Slack do.
- **The Search button comes alive.** It opens the dialog and carries `aria-haspopup="dialog"` and `aria-keyshortcuts`, on the full sidebar and on the collapsed rail. 001 kept it inactive "until spec 009" (001 Q2), so 001's tests for that (AC-7) change to the new behaviour.
- **No new dependency** (Q4). The dialog is Radix Dialog, which the `radix-ui` package in `@devhub/ui` already installs. The result list is our own ARIA combobox and listbox, not `cmdk`.
- **New `@devhub/ui` parts** (Q3): `Dialog` (shadcn's dialog, restyled to tokens) and the search parts: the input head, the group label, the result row, and the loading, empty and error forms. Each gets a story per state and a test.

## Goal

From anywhere in DevHub I press ⌘K and type part of a ticket key, a pull request number or a title. Then I pick the one I want with the arrow keys and Enter. Search finds the tickets, pull requests and Claude sessions DevHub already knows about, at once, without leaving the page I'm on.

## Out of scope

- Asking Jira or GitHub while you type, to find tickets and pull requests DevHub hasn't synced: other people's issues, closed tickets, merged pull requests (Q1a).
- Slack messages (016).
- Commands in the dialog, such as New task, going to a place or switching the theme.
- Fuzzy matching, typo tolerance and marking the matched letters.
- Recent searches, or keeping the last search.
- Searching descriptions, comments or code. The cache holds titles and metadata only.
- Changing the search boxes on Home and Tickets, which narrow only their own page.
- A ticket or pull request page inside DevHub.
