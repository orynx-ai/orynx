# App shell and navigation

Status: approved
Roadmap: Phase 1 — Foundation

## Assumptions

Correct these now, or the work goes ahead on them.

- Spec 000 already built most of the sidebar: logo, the collapse button (saved in the browser), New task as a link to Home, a disabled Search button, the three places, an empty Sessions section, the Claude footer, the skip link and stacking below 768 px (`md`). This spec finishes the sidebar. It does not start over.
- **Sessions come from the server.** A new `GET /api/sessions` returns session summaries, newest activity first, with an optional `limit` (the sidebar asks for 5). Nothing creates a session until spec 011, so in this spec the server's session store holds sessions in memory and starts empty. Spec 011 swaps in the real store under `<DEVHUB_HOME>/sessions/` without changing the contract.
- A session summary is `id`, `title`, `state` (the five states already in `@devhub/contracts`), `source` (a Jira key like `PROJ-1423`, a pull request like `PR #2836`, or none) and `updatedAt`. With no source, the second line shows only the state word.
- A new server event `sessions.changed` refetches the session list, the same way `status.changed` refetches the status.
- The sidebar shows the 5 sessions with the newest activity. A session that needs you is not pinned to the top.
- With a name in the footer (Q6), the second line becomes "Claude connected · runs locally" or "Claude not connected · runs locally", like the design. The second wording is a guess.
- Session state words come from the product spec: "Needs you", "Working", "Done, ready for PR", "PR open", "Stopped".
- The Home and Tickets counts are not shown until specs 007 and 008 have the data. A place with no count shows no badge, not a "0".
- New task goes to Home and moves focus to the main region. When the composer ships (spec 015), it focuses the composer instead.
- The shortcut keys show `⌘` on macOS and `Ctrl` on other systems. The host's `Platform` tells the app which system it runs on.
- Shortcuts work even when focus is in a text field, because they use a modifier key.
- Esc and arrow keys in menus wait for the Menu component (spec 006). This spec keeps the arrow keys that already work in the Settings tab list.
- No new dependencies: shortcuts are a small hook in `@devhub/app`, not a hotkeys library.

Decided while building (16 Oct 2026), then settled by a person on 17 Oct 2026 (Q10–Q12):

- **Sidebar width** (Q10): 260 px by default. Drag its right edge, or use the arrow keys on it, to resize it between 260 and 400 px; the width is remembered in the browser. At 260 px the footer's longest line ("Claude not connected · runs locally") is cut with an ellipsis; its full text stays in the link's name.
- **The resize handle** (Q10) is invisible until hovered, focused or dragged, when a 2 px accent line marks the sidebar's edge. Screen readers hear it as "Resize sidebar, separator, 260 pixels". Left and Right move it 16 px, Home and End jump to 260 and 400 px, and a double-click resets it. Up, Down and modified arrows stay with the page and the browser.
- **Open for later:** resizing needs a drag or the keyboard; WCAG 2.2 (2.5.7, Dragging Movements) also asks for a single-pointer way, such as a width choice under Settings › Appearance. Not built in 001; raise it with spec 005 (Settings).
- **No name known:** the footer says "You" (Q6) with a person icon in the avatar slot, so the row keeps its shape when a name arrives and the collapsed rail still shows something.
- **The narrow-window Sessions place** uses Lucide's History icon; the design has no icon for it.
- **Session source keys are 12 px mono**, not the 11 px in the design's CSS, because the design system allows nothing under 12 px.
- **The Working icon spins** (the spec's "spinning arc"), except with reduced motion.
- **The web host waits up to 300 ms for the bundled fonts** before its first render, so text never moves when a font swaps in.

## Goal

Wherever I am in DevHub, the sidebar shows where I can go, my latest Claude sessions and their state, and whether Claude is connected. I can tuck the sidebar away and it stays that way, start a new task from the keyboard, and use it all on a narrow window or with a keyboard only.

## Out of scope

- The Home and Tickets counts (specs 007 and 008).
- The search dialog and what it finds (spec 009).
- Creating, starting, stopping or discarding sessions, and the Session screen body (specs 011–014).
- Removing merged or discarded sessions from the sidebar after 7 days (spec 011, once sessions have an end).
- Menus, Esc to close and arrow keys inside menus (spec 006).
- A keyboard shortcut to collapse the sidebar. Nobody asked for one.
