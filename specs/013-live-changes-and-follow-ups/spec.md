# Live changes and follow-ups

Status: approved
Roadmap: Phase 3 — Claude sessions

## Assumptions

Correct these now, or the work goes ahead on them.

- **This spec builds on 011 and 012.** 011 is merged (PR #19). 012 isn't merged yet: on 18 Oct 2026 it had 23 of 26 tasks done, with the browser check, the real run and /review left, in another session. 013 needs 012's code: the waiting calls, the `Bash` tool and the sandbox, the stepper's Test step, and the approval callout. This branch starts from `main` at PR #19, for the spec only. It moves onto `main` again once 012 merges, before /plan's first task. If 012 changes on the way, these questions get checked again then.
- **What 013 takes over from 011 and 012.**
  - The adapter's `sendMessage`, which rejects until now.
  - The right pane: the Changes and Ticket tabs. With them comes the two-pane layout that 011 Q9a put off.
  - Discard changes moves back under the Changes tab, as drawn (011 Q9c).
  - Open in VS Code (011, Out of scope).
  - Claude's questions (`AskUserQuestion`), which 012 sent here (Q2).
  - Continuing a Stopped session, which 011 left out (Q1).
- **How a follow-up reaches Claude.**
  - While Claude is working, the message goes into the input stream the session already has open (011 kept it open "for follow-ups"). Claude reads it after its current step.
  - Once Claude has finished or stopped, its Claude Code process has ended. Orynx then starts Claude Code again with the SDK's `resume` and Claude Code's own session id, which 011 already saves as `claudeSessionId`. It uses the same worktree and every option 011 and 012 set: tools, sandbox, `settingSources: []`, hooks off, the allow-listed environment, the note and `canUseTool`. Claude carries on with its earlier conversation, which Claude Code keeps under `~/.claude/projects/` (011 assumptions).
  - No Claude Code setting changes.
- **Claude gets exactly what you typed.** Nothing is added: no diff, no ticket text, no file (agent-runtime rule 5). A message holds at most 10,000 characters. Orynx keeps it with the session in `session.json` (0600), as a step in Claude's progress. The terminal log says only that a follow-up was sent, with the session id, never the text. `brief.md` stays the first brief.
- **Both rules from 011 still hold: one live session per ticket, and three working at once.** A follow-up on a Stopped session makes it live again, so it isn't offered when the ticket already has a newer live session. A follow-up that would make a fourth working session is refused with a line, and the text stays in the box.
- **The changes are read, never written.** The server compares the worktree on disk with the commit the branch started from. It uses read-only git through `simple-git` (already a dependency): `git diff` with `--no-ext-diff` and `--no-textconv`, and `git ls-files --others --exclude-standard` for new files. Hooks are off, with 011 Q8d's short environment. Orynx never runs `git add`, and never changes the worktree's index or files. From 013 on, Orynx records the starting commit when it makes the worktree. For sessions made earlier, it uses `git merge-base HEAD <base>`.
- **How the Changes tab stays live.** When one of Claude's edits or commands ends, the server tells open pages through the event stream. The event carries only the session's id, as 011's `session.changed` does. The page then refetches the file list and the diff on screen, at most once a second for each session. It also refetches when the window gets focus again, so edits you make yourself in VS Code show up.
- **The API.** Each body is a schema in `@devhub/contracts`.
  - `GET /api/sessions/:id/changes`: the changed files with their counts, the totals, and why there are none when there are none (Q10c).
  - `GET /api/sessions/:id/changes/diff?path=`: one file's lines, in 006's `DiffLine` shape. It answers only for a path that's in the current list. Any other path, including one with `..` or an absolute path, gets `404`. So nothing outside the worktree is ever read.
  - `POST /api/sessions/:id/messages`: `{ text }` is a follow-up. A message that can't go gets a reason (Q10d).
  - `GET /api/sessions/:id` also carries the ticket for the Ticket tab (Q7), whether the follow-up box is on and, if not, why, and the worktree's path for Open in VS Code (Q9).
- **The tab and the file you're looking at live in the address** (`?tab=ticket`, `?file=src/content/ContentList.tsx`), as Home's tab does (007). A reload keeps them. Changes is the default tab, and the first file is shown by default.
- **A message you haven't sent stays in its box** while you look at other pages, until you close the browser tab. It's kept per session, in the browser's memory (zustand, as the client-state skill says for composer drafts), never on disk. Sending clears it.
- **The Ticket tab works without Jira.** It shows what Claude was sent (Q7). From 013 on, Orynx keeps the ticket's key, type, title and description with the session when it starts. Older sessions read them back from `brief.md`. Status and due date come from the cache when it has the ticket.
- **No new dependency** unless Q8 answers otherwise.
- **Tests never run the real Claude Code (010, 011).** Core tests fake the SDK's `query()` at its boundary, as in 011 and 012. Git runs for real on a temporary repository in a temporary `DEVHUB_HOME`. The e2e fake Claude Code learns `--resume`, and to read a message that arrives in the middle of its run.

## Goal

While Claude works, I watch its changes appear file by file and read the diff right next to its progress. Once it's done, or whenever I want to steer it, I type into the box under its progress and Claude carries on in the same worktree with everything it already knows. The ticket it started from is one tab away, so I can check the change against what was asked.

## Out of scope

- Create pull request, pushing, the "PR open" state, and follow-ups once a PR is open (014).
- Home's composer, New task, context chips, and adding a ticket, PR, Slack thread or file to a follow-up (015). Follow-ups are text only: no images, files or pasted attachments.
- Doing anything to the changes from the Changes tab: reverting or keeping single files or hunks, editing, commenting on lines, a side-by-side view, word-level highlighting and syntax colours (006 Q6b).
- Comparing with the default branch as it is now, rebasing, and merge conflicts.
- Editors other than VS Code (Cursor, JetBrains), opening a terminal in the worktree, and copying the path.
- Showing a command's output, or Claude's text between tools (011 Q10a, 012). Claude's reply to a follow-up shows as its "Finished" summary.
- Editing the ticket. Orynx links out to Jira (product spec, "Not in version 1").
- Claude's questions with choices to pick from, unless Q2 says otherwise.
- Picking the model, and showing cost or quota.

## Design

`docs/design/screens/session.html` (and `session-light.png`, `session-dark.png`):

- The two panes under the stepper: Claude's progress on the left, the tabs on the right.
- The follow-up box at the end of Claude's progress: its hidden label, placeholder, hint and round secondary Send.
