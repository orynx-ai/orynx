## Assumptions

Correct these now, or the work goes ahead on them.

- **Build order, and what this builds on.** This branch starts from `main` at 163716d, which has 005 (Settings), 006 (the design-system parts) and 007's server half (PR #9: the Jira reader, each connection's working credentials, `cache.db` and the sync schedule). 007's Home screen (its tasks 16 to 22) is still being built in `../dev-hub-007`. 008 doesn't need it. Both specs touch `shell/sidebar.tsx` (the Home and Tickets counts), `live-updates.tsx`, the contracts index and the test MSW handlers, so whichever merges second rebases.
- **The sprint syncs with the inbox.** The sprint reads join 007's sync: once at start, every 2 minutes while a DevHub page is open, at once when Jira connects, and on Home's Refresh. Only one sync runs at a time. Tickets answers from `cache.db`, so it opens at once, and a finished sync refreshes Tickets in every open tab. The Tickets page has no Refresh of its own (Q8f).
- **What one sync reads from Jira**, through 007's `client.ts` and `jira.js` `sendRequest` (no new dependency). The exact requests are for `/plan`, within these limits:
  - which sprint is yours (Q1): your issues in open sprints (`assignee = currentUser() AND sprint in openSprints()`), with the sprint field. That field is found by its type (`com.pyxis.greenhopper.jira:gh-sprint`) in the site's field list, never by its name.
  - the sprint's board's columns (`/rest/agile/1.0/board/{id}/configuration`), for In review (Q2) and the project key in the page bar.
  - every issue in that sprint (`sprint = <id> ORDER BY Rank ASC`), sub-tasks included, at most 300, read 100 at a time. Each issue is checked on its own, so one odd issue is left out instead of failing the read.
  - the site's priority order (007 already reads it), for the priority bars (Q7a).
- **Statuses go by category and the board's columns, never by name.** Each column's statuses come from the board's configuration by status id (integration-adapter skill).
- **The cache.** The sprint's tickets join `cache.db`: key, summary, status name and column, type name, priority name and level, due date, the assignee's display name and whether it's you, and Jira's rank order. Also the sprint's name, end date, board and project key. Never a description, a comment or an acceptance-criteria field. The cache's version goes up, so a file an older DevHub wrote is made again (007 AC-29). Disconnecting Jira removes the sprint, and Clear cache empties it and syncs again.
- **Order.** Within a column, cards follow Jira's rank (the order the team's board shows). The list follows the columns, then rank.
- **Page width `full`.** The design-map keeps `full` for a board or table that 960 px would squeeze. The board scrolls sideways inside its own box, never the page. The scroll box is a focusable, named region, so the keyboard can scroll it.
- **Board or List is remembered on this computer**, in a persisted zustand store (client-state skill: "board vs list view"), not in the address.
- **Claude's state on a card** comes from the session store that exists today (`GET /api/sessions`, a session's `source.key`). Nothing creates a session until 011, so no card shows an agent chip until then (Q4c).
- **No Jira writes.** If Q5 is answered as recommended, 008 only reads.
- **The new `@devhub/ui` parts** (Q10) are built here, because 006 left board columns, the list table and the search field to 008 (006 Q1b).

## Goal

When I open Tickets I want my current Jira sprint laid out the way my team's board is: To do, In progress, In review and Done, with my tickets showing first. Each card should tell me at a glance what kind of ticket it is, how urgent it is, when it's due and whether Claude is on it. I can switch to a list, narrow it to bugs or to what's due this week, and find a ticket by typing its key or a word of its title.

## Design

`docs/design/screens/tickets.html` (and `tickets-light.png`, `tickets-dark.png`): the page bar (breadcrumb, sprint meta, Search tickets, Board / List), the toolbar (filter chips and count), the board (columns with status icon, name and count, and WorkItemCards with their agent chips), the list view's table, and the sidebar's Tickets count. Not the column + (Q5), the Build sparkle or the list's "Build with Claude" (Q4b), and not the title's link to `session.html` for a ticket that has no session (Q4a). The card is 006's `WorkItemCard` and `AgentChip`, and the filters are 006's `FilterChip`. Where the screen's sizes and weights are off Clean UI's scale, Clean UI wins (Q10d).
