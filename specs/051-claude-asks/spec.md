# Claude asks: a question in the session, answered there

Status: approved, every question answered (3 Nov 2026)
Roadmap: not on the roadmap. The user picked it from a list of next features on 3 Nov 2026 ("add this"). 051 is the next free number on `origin/main` and its branches.

## Assumptions

Correct these now, or the work goes ahead on them.

- **This reverses spec 013, Q2(a).** In 013, `AskUserQuestion` stayed off, and Claude put a decision it needed in its summary for you to answer in a follow-up. The user's ask on 3 Nov 2026 turns the tool on. The brief's line "If you need a decision from the user, finish and ask it in your summary" (`brief.ts`) changes to: "If you need a decision from the user before you can go on, ask it with AskUserQuestion. Ask only what the code, the brief and the repository's rules don't answer."
- **Every session that has tools gets the tool**: Build, Ask (with a folder or without), a review (spec 050) and a fix on your own pull request (spec 031). Orynx's calls with no tools stay as they are: the quick read of your ask (042), the pull request draft (014) and the commit message.
- **A question is not a permission.** It reaches you in every mode of Settings › Coding agent, including the freest one. It has no Always allow, and nothing is saved to the allow list.
- **A question waits the way an approval waits** (spec 012). It goes in the session's list of waiting calls, oldest first, and the session is Needs you. The answer goes through the same route, `POST /api/sessions/:id/approvals/:approvalId`, whose body gains an answer. Stop, a second tab answering first, and Orynx restarting all work as they do for an approval.
- **What Claude Code sends** (Agent SDK 0.3.302, `AskUserQuestionInput`): 1 to 4 questions. Each has a `question`, a short `header`, `multiSelect`, and 2 to 4 options with a `label`, a `description` and an optional `preview`. Claude Code adds its own "Other" choice, which Orynx draws as a choice with a text box.
- **What Claude gets back**: the call is allowed with `answers` added to its input, keyed by the question's text. That is the picked option's label, the labels joined by ", " for a multi-select, or the text you typed for Other. This is how the SDK expects a host to answer.
- **Orynx checks the call before showing it.** It needs 1–4 questions and 2–4 options per question, no empty question or label, and no question asked twice in one call (the answers are keyed by question text). A call that fails these is refused with no step, and Claude is told what was wrong: "Ask 1 to 4 questions, each once, with 2 to 4 choices that each have a label."
- **Other's text is at most 2,000 characters.** The text box says so only when you go past it.
- **Skip tells Claude:** "The user skipped your question. Carry on with your best judgement, and say in your summary what you assumed." (Q4)
- **A desktop notification never shows the question's text**, in the same way it never shows a command (spec 029). The question can hold code or names. It says "Claude has a question" with the ticket and the session.
- **The Terminal's Claude tab doesn't answer questions.** It answers only commands today, and edits wait in the session, so questions do the same.
- **You can't change an answer after it's sent.** You correct Claude with a follow-up instead.

## Goal

When Claude isn't sure how to go on, it should ask me right in the session, with its choices as buttons, wait for my pick, and carry on with my answer. Today it either guesses or finishes with the question in its summary, and I have to start it again with a follow-up.

## Out of scope

- Answering from the Terminal's Claude tab, from a desktop notification, or from Slack or Discord.
- A time limit or auto-continue on a question (the SDK's `askUserQuestionTimeout` stays at its default, never).
- A setting that turns questions off.
- Changing an answer after it's sent.
- Claude Code's plan approval (`ExitPlanMode`) and its other tools. Only `AskUserQuestion` is turned on.
- Questions in Orynx's calls that have no tools (the quick read, the pull request draft, the commit message).
