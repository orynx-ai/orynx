# First-use feedback

Status: draft
Roadmap: not on the roadmap. The user's feedback after using Orynx, 18 Oct 2026. It takes 020, the next free number after 019.

## Assumptions

Correct these now, or the work goes ahead on them.

- **One spec for eight fixes.** The user asked for eight fixes in one message and one worktree, so they share one spec and one branch, `feat/020-first-use-feedback` in `../dev-hub-020`. The branch starts from `origin/main` at the PR #20 merge (012). Specs 013 and 014 are being built at the same time. This spec stays out of the Session screen's files, so the branches don't collide.
- **The parts.** A: sessions in the sidebar. B: the collapsed sidebar. C: New task leaves the sidebar. D: tooltips. E: the local-first note. F: Ship on Home and Tickets. G: Settings › Repositories. H: Tickets' project, sprint and filters. Acceptance criteria are grouped by part.
- **A. Every session in the sidebar, 16 at a time.** The sidebar lists sessions newest activity first, 16 at a time. When the end of the list scrolls into view, the next 16 load below it. The 7-day rule stays: a session discarded more than 7 days ago leaves the sidebar but stays under View all. View all stays and still opens the full Sessions page. The server pages with a cursor (the last row's activity time and id), so a session that moves to the top while you scroll is never shown twice.
- **B. The collapsed sidebar gets a Sessions icon.** On the collapsed rail, under Settings, a Sessions icon opens the Sessions page, as the Sessions place in a narrow window does today. The rail still lists no session rows.
- **C. New task leaves the sidebar.** The New task button goes from the wide sidebar, the collapsed rail and the narrow bar. Home does the same job. ⌘N still goes to Home and puts focus on its content (spec 001), so the shortcut keeps working without the button.
- **D. Tooltips come from one component.** `@devhub/ui` gets `Tooltip` (Radix Tooltip, from the `radix-ui` package the design system already uses, so no new dependency) and `IconButton`. `IconButton` takes a `label`, which is both its accessible name and its tooltip, so an icon-only button can't ship without one. Every icon-only control gets a tooltip, and the `title` attributes they use today go. The list: the sidebar's Collapse and Expand, every icon on the collapsed rail (Search, Home, Tickets, Settings, Sessions, and the footer's name and Claude's state), the narrow bar's Search, Ship on a ticket card, the composer's Send, a context chip's Remove, the pagination arrows, Home's row icons (F), a folder's More actions (G), and the local-first note's close button (E). A tooltip opens when the pointer rests on the control, or at once when it gets keyboard focus. Escape closes it. A touch never opens one, so the name stays on the button for screen readers alone.
- **D. A gate keeps it that way.** A new `pnpm gate icon-buttons` fails when a `Button` with an icon size (`icon`, `icon-sm`) is used outside `IconButton`. All of today's icon buttons move to `IconButton` in this branch, so the gate can fail from the start. CLAUDE.md rule 7 says "give icon-only buttons a tooltip with `IconButton`", and `pnpm agent-rules` copies it into the other agent files.
- **E. The local-first note can be closed for good.** The "Everything stays on this computer" callout on Settings gets a close button. Once closed, it never shows again in this browser. The choice is a UI-only preference, kept like the sidebar's width (zustand, saved in the browser), so it is never sent to the server. A different browser, or a browser whose site data was cleared, shows it once more.
- **F. "Ship" names the action that starts Claude on a ticket.** "Build" and "Build with Claude" become "Ship" on Home, on ticket cards and in the Tickets list. Its accessible name says which ticket: "Ship PROJ-1423". It keeps the sparkles icon that ticket cards draw today, so one icon means one action everywhere. The session stepper's "Build" step stays: it names a step of the work, not this action.
- **F. Home's actions become icons with tooltips.** The row's title still links where it does today. Each row ends in icon buttons, always visible, each with a tooltip:
  - a Jira issue with no session: Ship (sparkles), then Open in Jira;
  - a pull request: Open in GitHub (this replaces Review and Open);
  - a session, or an issue whose session is live: Open session;
  - a Slack row, once spec 016 adds them: Open in Slack.
- **G. A folder's actions move into a menu.** Remove gives way to a More actions icon button (⋮) on each folder. Its menu: Edit, Duplicate, Delete. Delete forgets the folder at once, as Remove does today. Its description says the folder stays on disk. There's no confirm step, since nothing on disk changes and the folder can be added again.
- **G. Add, Edit and Duplicate open a dialog.** Add local folder opens the dialog instead of unfolding the form. Edit opens it filled in, and you can change the folder and the Jira project. This replaces spec 005 Q9, which kept editing out. The server checks an edited folder as it checks a new one. Duplicate opens it filled in with that folder's path and project (Q3 says what the server allows).
- **G. Ship's menu adds a folder without leaving the page.** When Ship opens its menu (several folders, or none, for the ticket's project), the menu ends with "Add local folder" and a + icon, as the design system draws the repo picker. It opens the same dialog, with the ticket's project picked. Once the folder is saved, Claude starts on the ticket in it at once. With no folder, the menu says "No folder is set for PROJ." above Add local folder, which replaces the link to Settings › Repositories.
- **H. Tickets can show any project's sprint.** Two pickers open the toolbar: Project, then Sprint. Until you pick, Tickets shows your sprint, as it does today: the active sprint that holds most of your tickets. The Project menu lists the Jira projects you can see (Settings › Repositories reads the same list), A to Z by key, and its first item is "Your sprint". The Sprint menu lists the picked project's active sprints, then its future ones, each with its dates. Closed sprints aren't listed. Your pick is saved on the server, in `settings.json`, so the 2-minute sync reads that sprint and the sidebar's Tickets count follows it. A picked sprint stays picked after it closes, until you pick another.
- **H. Five filters say what they filter.** Assigned to me, Due this week and Bugs only give way to five pickers, drawn like Home's filters (a plain picker, a count of ticked options, a menu of checkboxes). Options in one filter widen it (any of them), and filters narrow each other (all of them). Assignee starts as Me, as Assigned to me does today. Clear filters goes back to Assignee: Me and empties the search. The filters live in the address. Addresses from spec 008 still work: `assignee=anyone` means no Assignee filter, `due=week` means Due: This week, and `type=bug` means Type: Bug. The five:
  - Assignee: Me, Unassigned, then each person in the sprint, A to Z;
  - Status: each status in the sprint, in board order;
  - Type: each type in the sprint;
  - Priority: each priority in the sprint, in the site's order;
  - Due: Overdue, This week, No due date.
- **No new dependency**, and no new token. Infinite scroll uses the browser's `IntersectionObserver`, and the server pages with what `listSessions` already holds.
- **People-owned files.** `docs/product/spec.md` still says "five most recent sessions", "New task (⌘N)" and "Build with Claude". Agents can't edit it, so the branch leaves the user a script that makes those edits.

## Goal

Every session is one scroll away in the sidebar, even when it's collapsed, and Home is where new work starts. Every icon says what it does when I point at it. Home and Tickets say "Ship" for starting Claude, Home shows its actions as icons, and I can add a folder from the Ship menu without going to Settings. Tickets shows the project and sprint I pick, and its filters say what they filter.

## Out of scope

- Session rows on the collapsed rail, or a session popover there.
- Paging the Sessions page; it still lists every session at once.
- Closed sprints in the Sprint menu, picking several sprints at once, and a board that isn't a Scrum board.
- Searching inside the Project menu (Radix's type-to-jump works), and saved filter sets.
- A confirm step for Delete, and checking that saved folders still exist on disk.
- Slack rows themselves (spec 016); this spec only says which icon they get.
- Hiding other notes, or a setting to bring the local-first note back.
- Renaming the session stepper's Build step, and the `/ship` command.
