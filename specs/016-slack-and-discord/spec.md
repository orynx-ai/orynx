# Slack and Discord: who waits on your reply, a thread as Claude's context, and Fix this from a bug report

Status: approved
Roadmap: Phase 4 — Slack and polish, spec 016 (`016-slack`). The user asked on 2 Nov 2026 to "add slack and discord both in single pr", after picking "A Slack bug report becomes a fix in one flow" from that day's ideas. So Discord joins Slack in this spec, the slug becomes `016-slack-and-discord`, and Fix this with its reply in the thread is new. The branch is `feat/016-slack-and-discord`, made from `origin/main` at `a68f50e`. It reverses one choice from the product spec for this one case: "Not in version 1: writing Slack replies from inside DevHub" (Q2).

## Assumptions

Correct these now, or the work goes ahead on them.

**A. Connecting**

- **Slack keeps spec 030's two steps.** Step 1 is today's "Copy request for your admin". Its text now names every scope below. Step 2 is new: paste the user token (`xoxp-…`) of the Slack app your admin approved. Orynx checks it with Slack (`auth.test`, and that the token holds every scope) before it saves anything. The token goes to the OS keychain (account `slack`), and `DEVHUB_SLACK_USER_TOKEN` stays the opt-in `.env` fallback.
- **Slack scopes** (Q3): `search:read` (your mentions), `im:history`, `im:read`, `mpim:history` and `mpim:read` (DMs and group DMs), `channels:history` and `groups:history` (a thread's messages, and whether you replied), `channels:read`, `groups:read` and `users:read` (channels' and people's names), and `chat:write` (the one reply in E). One workspace per token. (Changed while building, 2 Nov 2026: the list Q3 approved had nine scopes, not ten, and left out `channels:read` and `groups:read`, which a pasted link needs for its channel's name. That makes eleven.)
- **Discord uses a bot you make, because a person's own account can't be used** (Q1). Discord's terms forbid automating a user account. Step 1 of Discord's dialog says how to make the bot: in Discord's Developer Portal, New Application, then Bot, then turn on Message Content Intent, then add the bot to your servers with View Channels, Read Message History, Send Messages and Send Messages in Threads. Step 2 is pasting the bot's token. Orynx checks it with Discord before saving it to the keychain (account `discord`, `.env` fallback `DEVHUB_DISCORD_BOT_TOKEN`).
- **"You" on Discord is the bot's owner.** Orynx reads the application's owner from Discord. When a team owns the application, step 2 also asks for your Discord user ID.
- **Discord sees less than Slack.** A bot sees only the servers it was added to, and it can never read your DMs. So Discord rows are only messages that mention you in those servers.
- **Settings › Connections gets a fourth row, Discord**, below Slack. It has the same row, status button and dialog as the other three (spec 030). The "Everything stays on this computer" line becomes "…Orynx talks only to Jira, GitHub, Slack, Discord and Claude."
- **Libraries.** Slack uses `@slack/web-api`, which `docs/architecture.md` already plans. It's added to `packages/core` and loaded on first use. Discord uses Node's own `fetch` against Discord's REST API v10 inside `integrations/discord/client.ts`, so it needs no library (Q4).

**B. On Home**

- **What counts as waiting on you.**
  - **Slack:** a message that @mentions you, or a DM or group DM to you, with no message from you after it in the same thread or DM.
  - **Discord:** a message that @mentions you in a server the bot is in, with no message from you after it in the same channel or thread.
  - **Neither:** `@here`, `@channel`, `@everyone`, role mentions and user-group mentions don't count, and nor do messages from bots or from you.
- **The wait is 2 h by default**, as the product spec's table says. It's one setting shared by both tools, in Settings › Inbox rules: 30 min, 1 h, 2 h, 4 h or 1 day. A message joins the list at the first sync after it has waited that long.
- **Orynx looks back 7 days.** An older message never shows. It checks at most 100 messages per tool per sync, longest wait first.
- **Each row is drawn as the design's Slack rows are:**
  - **Mark:** the tool's logo.
  - **Title:** the message's first line, up to 120 characters, with mentions and channels written as names ("@Neha K.", "#web-platform").
  - **Sub line:** Slack reads "Neha K. in #web-platform", or "Arjun M. · direct message" for a DM. Discord reads "Neha K. in #web-platform · Acme", with the server's name.
  - **Pill:** "No reply · 3 h", in the waiting colour.
  - **Reply:** opens the message in Slack or Discord through `Platform`. Inbox links accept only `https://<workspace>.slack.com` and `https://discord.com/channels/…`.
- **A row leaves the list** at the next sync after you reply, or when the message is 7 days old. Orynx has no "done" or "snooze" button.
- **Tabs:** All · Jira · Pull requests · Slack · Discord (Q6). Each tab is part of the address (`/?inbox=slack`, `/?inbox=discord`), as spec 007's tabs are. Slack's and Discord's tabs show only once that tool is connected.
- **Settings › Inbox rules gets two rows,** "Slack mentions and DMs you haven't answered" and "Discord mentions you haven't answered", both on by default. The shared wait goes under them. Turning one off hides its rows right away, without a sync.
- **Sync** runs every 2 minutes with the others. The Sync button, Sync activity (spec 035) and the per-tool failure line all name Slack and Discord, and a failing tool never stops the other tools' rows. When Discord answers that its search isn't ready yet (Discord indexes new servers first), the tool shows as syncing and tries again at the next sync.
- **The cache holds only each row:** the first line, names, ids and times. It never holds a thread. Clear cache removes the rows.
- **Notifications (spec 029):** the event spec 029 Q4 set aside joins Settings › Notifications under Inbox, as "Someone is waiting on your reply". It's on by default, like the other inbox events.
- **Search (⌘K) doesn't look in Slack or Discord.**

**C. A thread as Claude's context**

- **Adding a thread.** Paste a Slack message link or a Discord message link into the composer, and it becomes a chip, as a pull request link does (spec 015). The chip reads the sender and the channel: "Neha K. in #web-platform ×". + Add context gets a "Slack or Discord thread" item that lists the messages in your inbox, with a search. Each Slack and Discord row gets the Add to composer button pull request rows had before spec 050.
- **What the thread is.**
  - **Slack:** the whole thread. A message outside any thread is a thread of one message.
  - **Discord:** a thread channel's messages. A message outside a thread brings itself and the messages that use Discord's Reply on it, from the 100 messages after it.
- **The brief** gets a section like "Slack thread in #web-platform, started by Neha K., 2 Nov 2026". Under it each message reads "Neha K., 14:05: …", oldest first, with mentions written as names. Files and images appear by name only.
  - **Limit:** at most 200 messages and 40,000 characters. A longer thread keeps its first message and the latest ones, and says "150 earlier messages left out."
  - **Nothing else goes to Claude.** No Slack or Discord data goes to Claude except a thread you added (product spec, Security).
- **A thread Orynx can't read** stops the start, using spec 015's `context_failed` with the chip's place. The reasons are: the message was deleted, the bot isn't in that channel, or the tool isn't connected. Follow-ups take thread chips the same way.

**D. Fix this**

- **The button.** Each Slack and Discord row gets a Fix this `IconButton` (`WrenchIcon`, drawn as spec 047's Fix is) beside Reply. Its name is "Fix this: <title>".
- **It opens spec 019's New ticket dialog, filled in:**
  - **Title:** the message's first line, up to the title limit.
  - **Type:** Bug, when the project has one.
  - **Description:** "Reported by Neha K. in #web-platform: <link>", a blank line, then the message's text.
- **Where the ticket goes:** the dialog starts on the Jira project mapped to the composer's folder in Settings › Repositories. The ticket goes into that project's active sprint when there's exactly one, otherwise no sprint, in To do. When the folder has no project, or Jira isn't connected, the dialog starts on Orynx (spec 037). The dialog's Jira or Orynx choice stays, so you can switch (Q9).
- **Save makes the ticket, then starts a Build on it** in the composer's folder, with the composer's model and effort, and the thread as a chip in its context. The session opens. The composer's draft stays as it was, as with Fix (spec 047).
- **If Jira refuses,** its words show in the dialog and nothing starts (spec 019). If the ticket is made but the session can't start, the ticket stays and the reason shows with an Open ticket link. An example reason is three sessions already working.

**E. A reply in the thread**

- **When the callout shows.** Once a session's pull request opens (spec 014, or spec 047's later steps), and that session's context holds a Slack or Discord thread, the Session screen shows a callout, "Tell the thread". The first thread chip is the one used.
- **What it holds:** a text box with "A fix is up for review: <PR title> <PR link>", which you can edit (up to 2,000 characters), and Post reply and Not now buttons.
- **Nothing is posted until you press Post reply** (rule 11).
  - **Slack:** posts in the thread as you (`chat.postMessage` with the thread's `ts`).
  - **Discord:** your bot posts, as a Reply to the message, or in the thread channel.
  - **After posting,** the callout reads "Replied in #web-platform." with an Open thread link.
- **If posting fails,** the tool's words show (for example, the channel was archived), the text stays, and Post reply works again. Not now hides the callout for that session.
- **Nothing else is written** to Slack or Discord.

**F. Housekeeping**

- **`docs/product/spec.md` isn't edited here, because people own it.** The branch leaves the user a script for those edits, as specs 015 and 020 did. The edits are: Discord joins the integrations, "talks only to" and Security, and the "Not in version 1" line about Slack replies changes.
- **The roadmap's 016 row** gets the new slug and scope when this merges.
- **Logs and server events** carry ids and counts, never a message's text, a name or a token. Every integration has a leak test, like `no-token-leaks.test.ts`.

## Goal

The people waiting on my reply in Slack and Discord show up on Home next to my tickets and pull requests, with how long they've waited, so nobody waits for hours because I missed a mention. When a thread reports a bug, one Fix this makes the ticket and starts Claude with the thread as its brief. When the pull request opens, Orynx offers to tell the thread, and posts only when I say so.

## Out of scope

- The "Draft a Slack reply" quick start, and Claude writing any reply. The only write is E's reply with the pull request link.
- Discord DMs and Discord user tokens (A: Discord forbids both for this use).
- Watching a channel such as #bugs for reports that don't mention you.
- More than one Slack workspace, Slack Connect's other organisations, and Enterprise Grid.
- Search (⌘K) over messages, marking a message done, snoozing, reactions and emoji images (`:tada:` stays as text).
- The contents of files and images in a thread.
- Microsoft Teams, Google Chat and any other chat tool.
- Editing `docs/product/spec.md`: the branch leaves a script for it (F).
