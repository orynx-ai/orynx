# Sessions and worktrees

Status: draft
Roadmap: Phase 3 — Claude sessions

## Assumptions

Correct these now, or the work goes ahead on them.

- **This spec builds on 010.** It needs 010's Claude Agent SDK (0.3.302, pinned), `findSdkClaudeCode()`, the allow-listed environment in `packages/core/src/agents/agent-environment.ts` and the login check. 010 isn't merged yet (its review is running in another session). This branch starts from `main` (PR #14) for the spec. It moves onto `main` again once 010 merges, before /plan's first task, so no task builds on code that can still change.
- **What 011 takes over from 010 (010 Q1).** It covers the adapter's `startSession`, `onEvent` and `stop`, plus the open decisions in `.claude/skills/agent-runtime/SKILL.md` rule 6 (Q8). `respond` comes with approvals (012) and `sendMessage` with the follow-up box (013).
- **Where a session starts in 011.** From a Jira ticket only:
  - Tickets: the Build with Claude sparkle on a card and the "Build with Claude" button in the list (left out by 008 Q4b).
  - Home: "Build" on an assigned-issue row, where it says "Open" today (007 Q6).
  - Not from the composer or New task (015), and not "Fix" on a failing check (Q12).
- **One live session per ticket.** A ticket whose newest session isn't Stopped already shows that session's agent chip, not Build (008 Q4c). Home's row then says "Open" and opens the session. If two tabs press Build at once, the server starts one session and both tabs open it. A ticket whose newest session is Stopped shows Build again and starts a new session with a new branch (Q2). The old worktree stays until you discard it.
- **The ticket is read fresh from Jira.** The cache never holds a description (007, 008), so 011 adds one read when a session starts: `GET /rest/api/3/issue/<KEY>?fields=summary,issuetype,description`. Orynx converts the description from Jira's document format to plain Markdown with a small converter of its own, so there's no new dependency. Comments and custom fields aren't read (Q5).
- **The session's title is the ticket's summary.** Like today's sidebar row, the session shows the title, the key (`PROJ-1423`) and the state.
- **Where things go.** The session id is 16 random hex characters, like a repository's.
  - The worktree is `<DEVHUB_HOME>/worktrees/<session id>`.
  - The session is kept in `<DEVHUB_HOME>/sessions/<session id>/`: `session.json` (title, key, folder, branch, base, state, step, Claude's steps, times) and `brief.md` (exactly what Claude was sent). Folders are mode 0700 and files 0600, like 010's `claude-check`. Nothing about a session goes into `settings.json` or `cache.db`.
  - Claude Code also keeps its own transcript under `~/.claude/projects/`, as it does for any session. 013 needs it to send a follow-up after Claude finishes.
- **The main checkout's files are never touched.** Orynx runs only `git fetch`, `git worktree add -b`, `git worktree remove` and `git branch -D` against the folder. Those add the branch and the worktree's entry inside the folder's `.git`. Its checked-out branch, its files and its uncommitted changes stay as they were.
- **Claude's text isn't streamed word by word.** Claude's progress grows one step at a time (Q10a). A step reaches every open tab through the event stream:
  - `sessions.changed` when a session starts, changes state or ends. The sidebar, Tickets, Home and search refetch.
  - A new `session.changed` event, with the session's id, when its steps change. The Session screen refetches the new `GET /api/sessions/<id>`.
- **A restart stops a running session.** Claude Code runs as a child of the server, so it ends when Orynx stops. On the next start, a session that was Working shows Stopped with the step "Orynx closed while Claude was working" (Q10). Its worktree keeps the changes.
- **Stop.** Stop asks Claude Code to stop, and ends the process if it's still running 5 seconds later. Stop works while the worktree is being made too: whatever was made stays, and Claude never starts.
- **Discard.** Discard stops a working session first, then removes the worktree (`git worktree remove --force`) and deletes the branch (`git branch -D`). A worktree you deleted yourself is not an error: Orynx prunes it and carries on. The session stays Stopped, says the changes are gone, and stays under View all. It leaves the sidebar 7 days later (product spec, "Cleaning up"). Nothing has been pushed in 011, so deleting the branch loses only Claude's local work, and the confirm step says so.
- **The log stays quiet.** The terminal log names each session and step kind (session id, ticket key, `git` exit codes, Claude Code's error kind). It never logs the description, the brief, Claude's messages, file contents or the account.
- **Tests never run the real Claude Code (010).** Core tests fake the SDK's `query()` at its boundary: it's passed to `createServer()` the way 010 passes the program. Git runs for real against a temporary repository in a temporary `DEVHUB_HOME`. The e2e run reuses 010's `DEVHUB_CLAUDE_CODE` with a fake Claude Code that plays one scripted run, so the real SDK is between them. No new setting.
- **The new dependency is `simple-git`.** `docs/architecture.md` already lists it as planned for the session spec.
- **The SDK's defaults are switched off explicitly.** Left out, `settingSources` loads every settings file and `permissionMode` falls back to Claude Code's own default. So Orynx always passes:
  - `settingSources` (Q7) and `permissionMode: 'default'`, so every tool call that Claude Code doesn't allow by its own rules comes to Orynx's `canUseTool`.
  - `env` from the allow list. The SDK replaces the environment rather than adding to it.
  - `cwd` set to the worktree, and `tools` limited to the set in Q6.

## Goal

When a ticket is ready, I press Build with Claude and Claude starts on it in its own branch and worktree, so my checkout is never touched. I watch which step it's on (Plan, Build, Test, Review) and what it has done so far, and I can stop it, or throw its work away, at any time.

## Out of scope

- Approvals (012): asking about a command, Allow once, Always allow and Deny, the allow list, the amber callout, and the "Needs you" state. In 011 Claude can't run commands (Q6).
- The Changes tab with its file list and live diff, the Ticket tab, the follow-up box, and Open in VS Code (013).
- Create pull request, pushing, and the "PR open" state (014). The button stays out of the title row until 014.
- The composer, New task, sessions without a ticket, and context chips (015). Slack threads as context (016).
- "Fix" on a failing check (Q12).
- Resuming a Stopped session, picking the model, and showing cost or quota.
- Removing worktrees after a PR merges (014), and disk use in Settings.
- The More actions (⋯) menu in the page bar, until something goes in it.
