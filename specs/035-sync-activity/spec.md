# Sync activity

Status: approved
Roadmap: not on the roadmap. The user's ask, 20 Oct 2026, with the design "10b · Sync activity (modal)" (HTML). It takes 035, the next free number (030–034 are taken). The branch is `feat/035-sync-activity` in `../dev-hub-035`, from `origin/main` at 2b9881c (PR #40, spec 030).

## Assumptions

Correct these now, or the work goes ahead on them.

- **Every word says Orynx**, never DevHub (CLAUDE.md). "Slack stopped accepting DevHub's login" becomes "…Orynx's login", and so on.
- **Colours are this repo's tokens, not the design's.** Every colour the design uses already exists here (`--success`, `--warning`, `--danger`, `--border-control` and their `-subtle` forms). Its sizes map to the type scale and its 600 weight to `font-medium`, as `docs/design-map.md` says.
- **The marks are today's brand logos** (`SourceMark`, 17 Oct 2026), not the design's letters.
- **Only the tools Orynx syncs are listed: Jira and GitHub.** The design's other ten tools (Slack, Confluence, GitLab, Sentry, Calendar, Notion, Discord, Linear, PagerDuty, Bitbucket) don't exist on `main`. Slack joins with 016 and Discord with 034. Claude is a login, not a sync, so it isn't listed.
- **Two results, not three.** Orynx reads GitHub in one GraphQL query, so a sync can't be "2 of 3 repos". A sync either worked (green) or failed (red). The design's amber "Partly synced" isn't built. A failure Orynx fixes on its own (rate limit, no answer) gets an amber callout, and one you must fix (token refused, sign-in needed) gets a red one.
- **Orynx starts keeping a sync log.** Every sync of each tool writes one row: when it started, how long it took, worked or failed, the problem if it failed, and what changed. The log lives in `~/.devhub/cache.db` beside the inbox and keeps 30 days, as the design's foot says. Clear cache empties it. Upgrading adds the new table and keeps the inbox and notifications as they are.
- **What changed** compares the tool's items before and after the sync. New: an item that wasn't there. Removed: an item that left. Updated: an item that is still there with something different (title, status, reason, checks). Each change shows its kind, its key (`PROJ-1431`) or repository and number (`web-app #482`), and the item's title. A row keeps its first 50 changes and says "and N more" for the rest. The first sync after you connect a tool lists every item as new.
- **Open** on a change opens the item in Jira or GitHub, outside Orynx, with the external-link arrow (the user's rule). A removed item keeps its link.
- **Per-tool Sync now syncs that tool only.** Sync all now is today's Refresh: it syncs every connected tool. One sync runs at a time, as today, so a second press waits for the first. Retry in a problem callout is that tool's Sync now.
- **No retry policy is added.** Orynx syncs every 2 minutes while a page is open, as today. A failing tool is tried again at each sync. The design's "failed syncs retry 3 times" and "Auto-retry stopped after 3 tries" aren't built. The foot says "Syncs every 2 min while Orynx is open · log kept on this computer for 30 days".
- **Stats per tool**, as drawn: Last good sync, Next sync (the last sync plus 2 min), Changes today (since local midnight), and "Success, last 2 h" as "N of M" syncs.
- **The history shows the newest 100 syncs that match** the tool and the All/Failed filter, newest first. A sync from an earlier day shows its date before its time ("19 Oct 09:57"). Times use Orynx's clock format, as the inbox does.
- **The failure line** in an opened row is the problem in Orynx's words (today's inbox line: "Jira refused the saved token."), not the raw HTTP error, which Orynx doesn't keep. Copy copies that line.
- **Reconnect and Connect** go to Settings › Connections and open that tool's connection dialog (030), through a new `tool` search parameter. The modal closes.
- **The modal updates live.** `inbox.changed` already fires after every sync, so the open modal reads the log again. Other tabs see a sync when it ends, not while it runs. Only the tab that pressed Sync now shows its spinner.
- **The button shows only when a tool is connected**, like today's Synced line and Refresh.
- **Escape, Close and Done close the modal** and put focus back on the button that opened it. Radix keeps focus inside while it's open.
- **Security.** The log holds item keys, titles, links, times and problem kinds, the same things the inbox cache holds. It never holds a token, a request or a response body. It is served only to the page that holds the session token, as every route is. Nothing new reaches Jira or GitHub beyond the reads a sync already makes.
- **No new dependency.** Everything comes from `@devhub/ui` and what it already uses.
- **People-owned files aren't edited here.** The branch gives you a script that copies the design into `docs/design/screens/sync-activity/` and adds the new parts (Q4) to `docs/design/design-system.md`.

## Goal

When my inbox looks wrong or old, I can see why without leaving Home: which tool is failing, since when, what Orynx tried and what fixes it. I can also see what each sync brought in. One button on Home opens a sync log for every connected tool, and I can sync any tool again from there.

## Out of scope

- Every tool Orynx doesn't sync yet. Slack joins with 016 and Discord with 034.
- "Partly synced" results, auto-retry policies ("retry 3 times") and changing the 2-minute interval.
- A "sync started" event for other tabs. They see a sync when it ends.
- Raw HTTP errors in the log.
- Logging the Tickets sprint read on its own. Jira's rows cover the inbox read only.
- The design's sidebar and its Settings › Connections backdrop. Orynx's own shell stays.
- Any item from Q1, Q4 and Q5 that the answers leave out.
