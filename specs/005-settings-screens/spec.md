# Settings screens

Status: approved
Roadmap: Phase 1 — Foundation

## Assumptions

Correct these now, or the work goes ahead on them.

- **Build order.** On 2026-10-17 the user picked this order after 004: this spec, then 006 (design-system components), then Claude (010) and Home (007), with Slack (016) still near the end. The roadmap table is reordered to match. Spec 010, already written, waits on its own branch.
- **Five tabs, in the product spec's order.** Connections · Coding agent · Repositories · Inbox rules · Appearance. The new tabs live at `/settings/coding-agent`, `/settings/repositories` and `/settings/inbox-rules`, and a reload stays on the tab. Connections and Appearance are already built and don't change.
- **Changes save as you make them.** There's no Save button. Each change goes to the server at once, the control shows the new value straight away, and the page bar keeps saying "Changes save automatically" (already built). If a save fails, the control goes back to the saved value (Q7).
- **Where the settings live.** In `<DEVHUB_HOME>/settings.json`, next to Jira's and GitHub's, under new keys: the permission mode, the list of folders with their Jira projects, and which inbox rules are on. Saving one of these leaves every other key as it was. The theme stays in the browser, as spec 001 built it.
- **The permission mode is saved now and used later.** Nothing can start a Claude session until 011, and the rules each mode stands for are enforced in 012. The default is "Edit files freely, ask before commands", as the product spec says. The allow list behind the third mode is shown and edited in 012.
- **The inbox rules are saved now and used by Home (007).** All are on by default. Home doesn't exist yet, so turning one off changes nothing you can see until 007.
- **Adding a folder runs nothing in it.** DevHub reads the folder with the file system only. It checks that the folder exists, that DevHub can read it, and that it's the top of a git repository (it holds `.git`, as a folder or as a worktree's file). It never runs git or any script there. It saves the real path, with symlinks resolved, and shows it with `~` for your home folder.
- **A folder has at most one Jira project, and a project can belong to several folders.** When a ticket's project has more than one folder, the session spec (011) decides which one to use.
- **Your Jira projects are read when the form opens.** DevHub asks Jira for the projects you can see (using the connection from spec 003), keeps the list only while the form is open, and shows each one as "PROJ · Project name". No list is cached.
- **At most 100 folders.** That is far more than one person needs, and the form says so if you reach it.
- **Another open DevHub tab follows along.** A saved change sends a new `settings.changed` event, so every open tab shows it without a reload.

## Goal

I want to tell DevHub how Claude should behave, which folders on my laptop it may work in and which Jira project each one belongs to, and what counts as "needs you" on Home. I set each of these once in Settings, it saves as I go, and it's still there the next time I start DevHub.

## Out of scope

- The Claude card and the "More agents" card on the Coding agent tab (010, Q1).
- Using the permission mode, and the allow list (011 and 012).
- Using the inbox rules (007), and the Slack rule and Slack wait time (016, Q6).
- "Clear cache" (007, spec 002 Q3).
- A native folder picker. The desktop app can add one later through `Platform` (Q3).
- Changing a saved folder's Jira project in place (Q9), and checking that saved folders still exist.
- The "added on first run" set-up flow from the product spec's Settings table.
- Anything on the Connections and Appearance tabs.

## Design

`docs/design/screens/settings.html`, three tabs:

- **Coding agent:** the permission-mode fieldset and its footnote (not the agent cards, Q1).
- **Repositories:** the intro line, Add local folder, and the folder rows (name, path, Jira pill, Remove).
- **Inbox rules:** the intro line and the checkbox rows.

The HTML leaves the tabs' text as placeholders (mode lines, rule text, sample folders), so the wording comes from the product spec's Settings section and from Q8.
